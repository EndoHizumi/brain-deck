# PW-SH2 のキー配列

Sharp Brain PW-SH2 の本体キーと、Brainux のカーネルが出す Linux のキーコードの対応。
設定ファイルの `keys` には、この表の「KEY_* 名」を書く。

2026-10-03 に、次の 3 つを突き合わせて確かめた。

- **ソース**：linux-brain（`a9f534c7f53e`、実機のカーネル `6.1.70-ga9f534c7f53e`）の `arch/arm/boot/dts/imx28-pwsh2.dts` の `&keyboard_i2c` と、`drivers/input/keyboard/brain-kbd-i2c.c`。実機の `/sys/firmware/devicetree` から読んだ keymap も、ソースと同じだった。
- **wiki**：https://wiki.brainux.org/beginners/get-started/#キーボード の、PW-SH2 が入るグループ（Sx1〜Sx3、HC4〜HC6、SR1。デバイスツリーは imx28-pwsh2）と、keymap.png。
- **実機**：デーモンを `-v` で起動し、全キーを順に押して届いたイベントを記録した。

## 「記号」キーの扱い

「記号」（Brain のコード 0x19）は、ドライバが `symbol_mode` を切り替えるだけで、イベントは出さない。デーモンからは見えない。

- **記号を押しているあいだ**：dts の `keymap-symbol` にあるキーは、上の表の「記号を押しながら」のコードで届く。例：Q は KEY_1。
- **keymap-symbol にないキー**：A、S、Z〜B、スペース、決定、戻る、矢印は、ドライバが捨てる。記号を押しているあいだ、これらは使えない。
- **押したまま記号を押す、離す**：ドライバは、キーの状態が次に変わったとき（ふつうは離したとき）に、前のコードの「離す」を送ってから、新しいコードでその状態（離す）を送る。新しく「押す」は送らないので、余計な文字は入らない（`drivers/input/keyboard/brain-kbd-i2c.c` の `handle_symbol_key`、`handle_normal_key`）。デーモンは、押したときの割り当てで離すので、押しっぱなしにはならない。
- **設定での使い道**：KEY_1 や KEY_GRAVE などに割り当てを書けば、「記号」を、ハードウェアのレイヤーキーのように使える。シフトを押しながらの記号（wiki の「記号 + Shift」）は、KEY_LEFTSHIFT と組み合わせた入力として届く。

## 同時押し

実機で確かめた組み合わせ。

| 組み合わせ | 結果 |
| --- | --- |
| 文字切り替え + 文字キー（Q〜P、A〜L、Z〜M、−、BS、シフト）を 1 つ | すべて認識された |
| 文字切り替え + スペース、決定、戻る、← ↑ ↓ → | すべて認識された |
| シフト + 文字キー（Q〜P、A〜L、Z〜B）を 1 つ | すべて認識された |
| ページアップ（Ctrl）+ 文字キー、−、BS、スペース を 1 つ | すべて認識された |
| 文字切り替え + ページアップ + Z | 認識された |
| シフト + ページアップ + Z | 認識された |
| 文字切り替え + シフト + Q | 認識された |
| シフト + ページアップ + 文字切り替え | 認識された |
| W + E + R（3 つの文字キー） | 認識された |
| **文字切り替え + Q を押したまま W** | **W が届かなかった** |
| **記号 + シフト + G**（記号とシフトの順はどちらでも） | **G が届かなかった**（シフトだけが届く。2026-10-08、端末モードで記録） |
| 記号 + シフト + K、記号 + G | 認識された |

- **キーボードの制約**：ドライバは 1 回の割り込みで最大 3 キー（`BK_N_ROLL_MAX`）を読む。キーボードの回路（マトリクス）にも、同時押しできない組み合わせがある。
- **レイヤーキーへの影響**：文字切り替えをレイヤーキー（layer_hold）にして、そのレイヤーで 2 つの文字キーを同時に押すと、片方が届かないことがある。修飾キーを含む 3 キーの組み合わせは、ショートカットを 1 つのキーに割り当てて避ける。2 つ目のキーが必要なときは、layer_oneshot か layer_toggle を使う。

## レイヤーキーの候補

| 候補 | 向いている使い方 | 理由 |
| --- | --- | --- |
| **文字切り替え**（KEY_LEFTALT） | layer_hold | 左手の親指で押しやすい。文字キー・スペース・矢印との 2 キー同時押しが、すべて通った。PC に Alt を送れなくなるが、必要ならレイヤーの中で LALT を割り当てられる |
| マイ辞書（KEY_PAGEDOWN）、国語（KEY_TAB）など辞書キー | layer_oneshot、layer_toggle | 押したまま他のキーを押すには遠いので、押して離す使い方に向く |
| 調べる・戻る（KEY_ESC） | layer_to base | 2 つのキーが同じコードなので、どちらでも base に戻れる |
| ページアップ（KEY_LEFTCTRL） | ― | ショートカットでよく使うので、Ctrl のまま残す |
| 記号 | ― | デーモンから見えないので使えない |

## 画面右の帯

画面の右側に印刷された「HOME ▲ ▼ ▶ ◀ 決定 戻る 操作機能」の帯は、**タッチに反応する**。

- **座標**：爪で押した生の座標は、x が 3770〜3860、y は印刷の 8 区画どおりに上から 3800 前後〜600 前後。
- **画面との区別**：x はキャリブレーション範囲（max_x 3938）の**内側**に出る。画面の右端（右の列の右側 40 ドットほど）を押したときと、同じ範囲になる。そのため、座標だけでは「帯」と「画面の右端」を区別できない。
- **設定での扱い**：`touch.soft_areas` に 8 区画の範囲を書いてある。レイヤーの `soft_keys` で割り当てた区画だけが、セルより優先される。割り当てていない区画を押すと、右の列のセルとして扱う。

| 区画 | soft_areas の名前 | y の範囲（生の座標） | 実測した y |
| --- | --- | --- | --- |
| HOME | home | 3377〜4095 | 3671、3768 |
| ▲ | up | 2949〜3376 | 3124、3282 |
| ▼ | down | 2522〜2948 | 2912、2751 |
| ▶ | right | 2095〜2521 | 2436、2347 |
| ◀ | left | 1667〜2094 | 1977、1929 |
| 決定 | enter | 1240〜1666 | 1575、1488 |
| 戻る | back | 812〜1239 | 1061、1007 |
| 操作機能 | menu | 0〜811 | 641、579 |

x の範囲は、どの区画も 3740〜4095。
