# 設定ファイルの形式

`/etc/lefthand/config.yaml` の形式。YAML と JSON のどちらでも書ける。JSON は YAML の一部なので、同じファイル名のまま JSON を書いてもよい。
設定 GUI（WebSerial）も、この形式をそのまま読み書きする。

- **検証**：`lefthand -check config.yaml` で、デーモンを起動せずに検証できる。誤りはすべてまとめて表示する。
- **JSON への変換**：`lefthand -dump-json config.yaml` は、検証したうえで、旧形式を layers の形にそろえた JSON を出力する。割り当ては、すべてオブジェクトの形（`{"key": "B"}`）になる。
- **知らない項目**：書き間違いを見逃さないよう、知らない項目があると読み込みに失敗する。
- **設定 GUI で保存したとき**：デーモンが YAML で書き直す（`lefthand -check` を通る形）。割り当ては 1 行（`KEY_A: LCTRL+Z`、`"0,0": {key: B, label: ブラシ}`）で、項目は名前順になる。**手で書いたコメントは消える**。前の版は `config.yaml.prev` に残る。
- **設定 GUI で変えられない項目**：`hid_device`、`keyboard`、`touch.device`、`touch` の有無、`display`（`press_style` を除く）は、開いているデバイスにかかわるので、動作中のデーモンには反映できない。ファイルを直接編集し、サービスを再起動する。プロトコルは [protocol.md](protocol.md)。
- **設定 GUI で編集しない項目**：`terminal` と `backlight` は、GUI では編集しない（GUI で保存しても残る）。ファイルを直接編集する。

## 全体

```yaml
hid_device: /dev/hidg0      # 送信先。省略可
keyboard: brain-kbd-i2c     # 本体キーボード。パスかデバイス名。省略可
touch: { ... }              # タッチパネルそのものの設定。省略するとタッチと画面を使わない
layers: [ ... ]             # レイヤー。最初のものが base
display: { ... }            # 画面表示。省略可
terminal: { ... }           # 端末モード。省略可（下の「端末モード（terminal）」）
backlight: { ... }          # 自動減光。省略すると減光しない（下の「自動減光（backlight）」）
```

| 項目 | 型 | 内容 |
| --- | --- | --- |
| hid_device | 文字列 | 既定は `/dev/hidg0` |
| keyboard | 文字列 | 既定は `brain-kbd-i2c` |
| touch | オブジェクト | 下を参照 |
| layers | 配列 | 1 つ以上。下を参照 |
| display | オブジェクト | enabled（真偽）、device（既定 `/dev/fb0`）、vt（0 で自動）、rotate（0、90、180、270）、press_style（下を参照） |
| terminal | オブジェクト | 端末モードの設定。下の「端末モード（terminal）」 |
| backlight | オブジェクト | 触らなければ画面を暗くし、消す。下の「自動減光（backlight）」 |

## touch：タッチパネル

どのレイヤーでも共通の、ハードウェアの設定。格子の大きさとセルは、各レイヤーに書く。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| device | 文字列 | 既定は `mxs-lradc-ts` |
| swap_xy | 真偽 | パネルの X 軸が画面の縦方向のとき true |
| min_x、max_x、min_y、max_y | 整数 | 画面の端に当たる生の座標。`lefthand -calibrate` で測る。min > max なら軸を反転 |
| soft_areas | オブジェクト | ソフトキーの名前 → 範囲。範囲は `{ x: [a, b], y: [c, d] }` で、パネルの生の座標（swap_xy の影響を受けない）。a と b の順はどちらでもよい |

## layers：レイヤー

```yaml
layers:
  - name: base              # 必須。ほかのレイヤーから参照する名前
    label: "基本"           # 画面の隅に出す名前。省略すると name
    keys: { ... }           # 本体キーの割り当て
    touch:                  # タッチの格子
      cols: 4
      rows: 3
      cells: { ... }
    soft_keys: { ... }      # ソフトキーの割り当て
```

- **base**：最初のレイヤーが base になる。名前は何でもよいが、`base` を勧める。base はいつも一番下にあり、外れない。
- **重なり**：layer_hold などで入ったレイヤーは、base の上に、入った順に積まれる。いちばん上が「今のレイヤー」で、画面の右上に label を表示する。
- **透過**：割り当てを探すときは、いちばん上から順に見る。書いていないキー・セル・ソフトキーは、下のレイヤーの割り当てを使う。
- **none**：`none` と書くと、そこで探すのを止めて何もしない。下のレイヤーの割り当ても使わない。

### keys

左に Linux のキー名（`KEY_Q` など）、右に割り当てを書く。PW-SH2 のキー名は [keymap-pwsh2.md](keymap-pwsh2.md) を参照。

### touch

| 項目 | 型 | 内容 |
| --- | --- | --- |
| cols、rows | 整数 1〜16 | 格子の列数と行数。base 以外では、両方とも省略すると base と同じ大きさ |
| cells | オブジェクト | `"列,行"` → 割り当て。左上が `"0,0"` |
| background | 文字列 | 格子全体に敷く壁紙（背景画像の id）。下の「背景画像」 |

- **格子の大きさ**：上から見て、最初に touch を持つレイヤーの格子を使う。touch を書いていないレイヤーは、下のレイヤーの格子をそのまま使う。
- **セルの透過**：格子の大きさが下のレイヤーと同じあいだだけ、書いていないセルは下のレイヤーのものを使う。大きさが違えば、書いていないセルは空になる。
- **判定**：触れた瞬間に、今の格子で決まる。指を滑らせても、レイヤーが変わっても、離すまで変わらない。

### soft_keys

`touch.soft_areas` の名前 → 割り当て。割り当てがある区画だけが、格子のセルより優先される。
今の重なりで割り当てがない区画を押すと、格子のセルとして扱う。

## 割り当て

キー・セル・ソフトキーのどれにも、同じ形で書く。

| 書き方 | 意味 |
| --- | --- |
| `LCTRL+Z` | キーを送る。`+` でつなぐ。大文字小文字は区別しない |
| `none` | 何もしない（下のレイヤーも使わない） |
| `{ key: LCTRL+Z, label: "取り消し" }` | キーを送る。label は画面のセルに大きく出す。`\n` で改行 |
| `{ layer_hold: edit }` | 押しているあいだ、edit を重ねる |
| `{ layer_toggle: edit }` | 押すたびに、edit を重ねる・外す |
| `{ layer_oneshot: edit }` | 次に押した 1 キーだけ、edit を重ねる。もう一度押すと取り消す |
| `{ layer_to: edit }` | base と edit だけにする（ほかの重なりは外す）。`layer_to: base` で base だけに戻る |
| `{ mouse: left }` | マウスの操作。下の「マウスの操作」 |
| `{ media: play_pause }` | メディアキー（再生、音量など）。下の「メディアキー」 |
| `{ usb_mode: toggle }` | USB の形の切り替え（マウスのオンとオフ）。下の「USB の形の切り替え」 |
| `{ terminal: toggle }` | 端末モードに入る・抜ける。下の「端末モード（terminal）」 |

- **オブジェクトの形**：`key`、`layer_hold`、`layer_toggle`、`layer_oneshot`、`layer_to`、`mouse`、`media`、`usb_mode`、`terminal` のうち、ちょうど 1 つを書く。`label` はどれにも付けられる。ウィジェットのセル（下の「ウィジェット」）では、どれも書かなくてよい。
- **セルの大きさ**：タッチのセルには `span: [列数, 行数]` を書ける（下の「セルの大きさ」）。
- **送れるキーの名前**：修飾キー（LCTRL、LSHIFT、LALT、LGUI、RCTRL、RSHIFT、RALT、RGUI）、A〜Z、0〜9、F1〜F24（F13〜F24 は PC のキーボードにないキー。ショートカット用）、ENTER、ESC、BACKSPACE、TAB、SPACE、INSERT、DELETE、HOME、END、PAGEUP、PAGEDOWN、UP、DOWN、LEFT、RIGHT、テンキー（KP0〜KP9、KPPLUS、KPMINUS、KPASTERISK、KPSLASH、KPDOT、KPENTER）、MINUS、EQUAL、LEFTBRACE、RIGHTBRACE、BACKSLASH、SEMICOLON、APOSTROPHE、GRAVE、COMMA、DOT、SLASH。
- **配列によらない記号**：記号は US 配列での位置を送るので、PC が日本語配列だと別の文字になることがある。`+` などはテンキーの名前で送ると配列によらない。例：Ctrl++ は `LCTRL+KPPLUS`。
- **レイヤーのセルの表示**：layer_* のセルは紫で描く。label を省略すると、行き先のレイヤーの label を大きく、切り替えの種類（押す間、切替、1回、移動）を下に小さく出す。

### マウスの操作（mouse）

```yaml
KEY_A: { mouse: left }                       # 押しているあいだ左ボタンを押す（ドラッグにも使える）
"3,1": { mouse: right, label: 右 }           # セル
"3,2": { mouse: scroll_down }                # 1 段送り、押し続けると繰り返す
```

| 値 | 動き |
| --- | --- |
| `left`、`right`、`middle` | そのボタンを、押しているあいだ押したままにする |
| `scroll_up`、`scroll_down` | 縦のホイールを 1 段回す。押し続けると、0.35 秒後から 0.07 秒ごとに繰り返す |
| `scroll_left`、`scroll_right` | 横のホイール（AC Pan）を同じように回す |

- **使える場所**：キー、タッチのセル、ソフトキー。ウィジェットのセルのタップにも書ける（`todo`、`calendar`、`trackpad` を除く）。
- **セルの表示**：label を省略すると「左クリック」「スクロール↓」などを大きく出す。label を書けば、それを大きく、操作の名前を下に小さく出す。
- **離すとき**：キーと同じく、押したときの割り当てで離す。そのうえで、**レイヤーが変わったときは、押しているマウスのボタンをすべて離す**（切り替えを起こした入力そのもののボタンは残す。layer_oneshot のレイヤーで押したボタンを、押したまま使えるようにするため）。設定の再読み込みと、デーモンの終了でも離す。
- **ボタンの重なり**：複数の入力で同じボタンを押しているときは、すべて離すまで押したまま。
- **USB**：USB がキーボードだけの形（起動したときの形）のあいだは、何も送らない。下の `usb_mode` でマウスをオンにする。

### メディアキー（media）

```yaml
"1,0": { media: play_pause, span: [2, 1] }   # 再生と一時停止
"2,1": { media: volume_up }                  # 音量を上げる
KEY_F12: { media: mute, label: 消音 }         # 本体のキーにも書ける
```

| 値 | 動き（HID の Consumer のページの番号） |
| --- | --- |
| `play_pause` | 再生/一時停止（0xCD） |
| `stop` | 停止（0xB7） |
| `next`、`previous` | 次の曲（0xB5）、前の曲（0xB6） |
| `fast_forward`、`rewind` | 早送り（0xB3）、巻き戻し（0xB4） |
| `volume_up`、`volume_down`、`mute` | 音量を上げる（0xE9）、下げる（0xEA）、ミュート（0xE2） |
| `brightness_up`、`brightness_down` | PC の画面を明るく（0x6F）、暗く（0x70）。Brain の画面ではない |
| `calculator`、`browser`、`mail` | 電卓（0x192）、ブラウザ（0x196）、メール（0x18A）を開く |

- **USB の形**：メディアキーは、**キーボードとマウスの形（`usb_mode: mouse`）のときだけ送れる**。起動したときのキーボードだけの形（ブートキーボード）は、BIOS や UEFI の画面でも使えるように、標準の形のままにしているため。キーボードだけの形のときに押しても何も送らず、`-v` のログに `media: ... not sent` と出す。画面では、セルの下の小さな文字が「マウスオフでは無効」になり、文字が暗くなる。
- **起動したときから送れるようにする**：`/etc/lefthand/gadget.env` に `HID_MOUSE=1` と書く（README の「メディアキー」）。
- **押している長さ**：押しているあいだ押したままにする。音量などを押し続けたときに繰り返すかは、PC の OS による。
- **同時に押す**：2 つまで同時に送る（3 つ目を押すと、古いものは送らない）。
- **使える場所**：キー、タッチのセル、ソフトキー、ウィジェットのタップ（`mouse` と同じ）。
- **セルの表示**：label を省略すると「再生/停止」「音量+」などを大きく出す。label を書けば、それを大きく、名前を下に小さく出す。
- **離すとき**：キーと同じく、押したときの割り当てで離す。設定の再読み込み、USB の付け直し、デーモンの終了でも離す。

### USB の形の切り替え（usb_mode）

```yaml
"3,3": { usb_mode: toggle }                  # 押すたびに、マウスのオンとオフを切り替える
KEY_F1: { usb_mode: mouse, label: マウス }    # マウスをオンにする
```

| 値 | 動き |
| --- | --- |
| `toggle` | キーボードだけ ⇔ キーボードとマウス |
| `mouse` | キーボードとマウスの形にする（すでにそうなら何もしない） |
| `keyboard` | キーボードだけ（ブートキーボード）の形にする |

- **起動したとき**：キーボードだけ（ブートキーボード。BIOS や UEFI の画面でも使える）。
- **USB を付け直す**：2〜3 秒、キー入力、SSH、シリアル（設定 GUI）が切れる。押しているキーとマウスのボタンは、先にすべて離す。
- **セルの表示**：label を省略すると「マウス切替」「マウスオン」「マウスオフ」を出す。
- **使える場所**：キー、タッチのセル、ソフトキー、ウィジェットのタップ。

### 端末モード（terminal）

Brain の画面とキーボードで、USB でつないだ PC にログインする（[README の「端末モード」](../README.md#端末モード)）。

```yaml
"3,3": { terminal: toggle, label: 端末 }     # 押すと端末モードに入る
KEY_INSERT: { terminal: on }                 # 履歴/しおり で入る
```

| 値 | 動き |
| --- | --- |
| `toggle` | 入る（端末モードのあいだは、本体キーとタッチは端末が使うので、ふつうは入るだけに働く） |
| `on` | 入る（すでに入っていれば何もしない） |
| `off` | 抜ける |

- **抜け方**：画面右の帯の HOME（`touch.soft_areas` に `home` があるとき）、本体の文字切り替え + 調べる/戻る（Alt+Esc）、設定 GUI のコンソールのタブ、`brain-deck terminal off`。端末モードのあいだ、本体キー、タッチ、ソフトキーは端末が使い、レイヤーの割り当ては働かない。
- **使える場所**：キー、タッチのセル、ソフトキー、ウィジェットのタップ。
- **セルの表示**：label を省略すると「端末」（`off` は「端末を出る」）を出す。
- **押していたキー**：入るときに、PC に送っているキーとマウスのボタンをすべて離す。レイヤーの重なりはそのまま残り、抜けると元に戻る。

設定の `terminal` で、つなぎ方を変えられる。どれも省略できる（書かなければ、ttyGS0 のシリアルで PC の getty にログインする）。

```yaml
terminal:
  font: wide            # wide（100 桁、既定）か narrow（200 桁）
  scrollback: 1000      # 履歴に残す行数（0〜10000）
  # シリアル（既定）
  port: /dev/ttyGS0     # 使うシリアル
  getty: serial-getty@ttyGS0.service   # 端末モードのあいだ止める Brain の getty。none で止めない
  # コマンド（ssh など）。書くと、シリアルの代わりにこのコマンドを Brain の上で PTY につないで動かす
  command: [ssh, -t, me@192.168.7.1]
  user: user            # command を動かすユーザー（必須。root は不可）
```

| 項目 | 内容 |
| --- | --- |
| `font` | `wide`：k8x12 の全角英数の字形（8×12）で 1 桁 8 ドット、800 ドットで 100 桁。`narrow`：半角の字形（4×12）で 200 桁。行はどちらも 31 行（下にタッチのキー 2 段） |
| `scrollback` | 画面から流れた行を覚える数。▲▼ のソフトキーか Shift+英和/マイ辞書（PageUp/PageDown）で見る |
| `port` | 既定 `/dev/ttyGS0`（PC から見て 1 つ目のシリアル、`-if03`） |
| `getty` | 端末モードのあいだ止め、抜けたら起動し直す Brain の getty。既定 `serial-getty@ttyGS0.service`。止めていなければ、起動もしない |
| `command` | シリアルの代わりに動かすコマンドと引数。USB の付け直しも getty の停止もしない。端末の大きさは PTY でそのまま伝わる |
| `user` | `command` を動かす Brain のユーザー。ログインはしない（パスワードを聞かない）。環境変数は TERM、HOME、USER、LANG（en_US.UTF-8）、PATH、BRAIN_TERMINAL=1 だけ |

- **反映**：端末モードに入るときに読む。設定 GUI で保存したあとも、再起動は要らない（今入っている端末モードは、抜けて入り直すと変わる）。
- **設定 GUI**：`terminal` の項目は GUI では編集しない（保存しても残る）。ファイルを直接編集する。
- **検証**：`font` が wide か narrow でない、`scrollback` が範囲外、`port` が `/dev/` で始まらない、`getty` が `.service` で終わらず none でもない、`command` があるのに `user` がない、`user` が root のときは誤り。

### セルの大きさ（span）

```yaml
"0,2": { key: ENTER, span: [3, 1], label: "決定" }   # 0,2 から右へ 3 列ぶん
"0,0": { widget: clock, span: [2, 2] }               # 2 列 × 2 行
```

- **書き方**：`[列数, 行数]`。それぞれ 1〜16。書かなければ `[1, 1]`。セルの番号は左上のセルで書き、右と下に広がる。
- **使える場所**：タッチのセルだけ。本体キーとソフトキーには書けない。
- **押したとき**：覆う範囲のどこを押しても、そのセルを押したことになる。押したときの枠も、範囲全体に描く。
- **格子からはみ出す、重なる**：誤りになる。同じレイヤーの中で、span の範囲に別のセルを書いたときも誤り（両方のセルに誤りを出す）。
- **レイヤーの透過**：span のセルは、覆う範囲がすべて上のレイヤーで空いているときだけ出る。一部でも上のレイヤーのセル（`none` を含む）に隠れると、そのセルは出ず、隠れていない範囲は空になる。
- **格子の大きさが違うレイヤー**：今までどおり透過しない。

### ウィジェット

タッチのセルに、キーの代わりに情報を出す。今あるのは時計（`clock`）、テキスト（`text`）、Todo（`todo`）、カレンダー（`calendar`）、月の表示（`month`）、天気（`weather`）、グラフ（`graph`）、トラックパッド（`trackpad`）、電池（`battery`）、ストップウォッチ（`stopwatch`）、ポモドーロ（`pomodoro`）、カウンター（`counter`）、QR コード（`qr`）、在席ランプ（`presence`）、プレゼン用タイマー（`presenter`）。

```yaml
"0,0": { widget: clock }                                       # 時刻と日付。既定の書式
"2,0": { widget: clock, format: "15:04:05", date_format: none } # 秒まで出す。日付は出さない
"3,0": { widget: clock, tz: America/Los_Angeles, label: LA, key: F5 }  # 見出しを付け、タップで F5 を送る
"2,1": { widget: text, id: build, label: ビルド }                # テキスト。中身は PC の brain-deck で書き換える
"0,0": { widget: todo, span: [2, 3], label: Todo }              # Todo の一覧。長押しで完了を切り替える
"0,0": { widget: calendar, span: [2, 3], label: 予定 }          # 今日の予定と次の予定
"0,0": { widget: month, span: [2, 2] }                          # 月の表示（卓上カレンダー）
"0,0": { widget: weather, span: [2, 1] }                        # 今日と明日の天気。予報は PC の brain-deck が送る
"0,0": { widget: graph, id: cpu, unit: "%", min: 0, max: 100 }  # グラフ。値は PC の brain-deck graph cpu 12.5 で足す
"2,0": { widget: battery, label: 電池 }                         # 電池の残りと、USB から給電しているか
"0,0": { widget: stopwatch, span: [2, 1] }                      # タップで開始と停止、長押しで 0 に戻す
"0,1": { widget: pomodoro, span: [2, 2], work: 25m, break: 5m } # タップで開始と一時停止、長押しで最初に戻す
"3,0": { widget: counter, id: coffee, label: コーヒー }          # タップで +1、長押しで 0 に戻す
"0,0": { widget: qr, id: share, span: [2, 3] }                  # QR コード。中身は PC の brain-deck で送る
"2,0": { widget: presence, span: [2, 2] }                       # 在席ランプ。タップで次の状態
"0,0": { widget: presenter, duration: 20m, span: [2, 2] }      # プレゼン用タイマー。タップで開始と一時停止
```

| 項目 | 内容 |
| --- | --- |
| `widget` | ウィジェットの種類。`clock`、`text`、`todo`、`calendar`、`month`、`weather`、`graph`、`trackpad`、`battery`、`stopwatch`、`pomodoro`、`counter`、`qr`、`presence`、`presenter` |
| `label` | セルの上に小さく出す見出し（省略可） |
| `key`、`layer_*`、`mouse` | タップしたときの動き（省略可）。書けば、ふつうのセルと同じく働き、押したときに枠が光る。書かなければ、タップしても何もせず、枠も光らない。`todo`、`calendar`、`month`、`trackpad` には書けない（押した位置で働くため）。`stopwatch`、`pomodoro`、`counter`、`presence`、`presenter` にも書けない（タップと長押しを自分で処理するため） |
| `id` | `text`、`qr`、`graph`：中身の名前（必須）。`stopwatch`、`pomodoro`、`counter`、`presence`、`presenter`：状態の名前（省略すると種類の名前。同じ id のセルは同じ状態を出す）。英数字と `_ . -` の 32 文字まで |
| `span` | セルの大きさ。上を参照 |

- **使える場所**：タッチのセルだけ。本体キーとソフトキーには書けない。
- **`key: none` は書けない**：ウィジェットを出すだけなら、key を省略する。
- **描き直し**：ウィジェットごとに、中身が次に変わる時刻まで待って、変わったセルだけを描き直す。描画は今までどおり別のスレッドで行い、入力の処理を待たせない。壁時計が NTP などで飛んでも、1 分以内には表示が追いつく。
- **データ**：テキスト、Todo、カレンダー、天気、グラフの中身は、設定ファイルではなく `/var/lib/lefthand/` に置く。設定 GUI で設定を保存しても消えない。
- **ほかの種類の項目**：`format` などの時計の項目をテキストに、`id` を時計などに、`rows` を Todo とカレンダー以外に、`page_reset` を Todo、カレンダー、月の表示以外に、`stale` をカレンダー、天気、グラフ以外に、`unit`、`min`、`max`、`chart`、`points`、`decimals` をグラフ以外に、`follow` をカレンダー以外に、`calendars` をカレンダーと月の表示以外に、`week_start` を月の表示以外に、トラックパッドの項目をトラックパッド以外に、`work` と `break` をポモドーロ以外に、`states` を在席ランプ以外に、`duration` と `colors` をプレゼン用タイマー以外に書くと誤り。
- **タップと長押し**（`stopwatch`、`pomodoro`、`counter`、`presence`、`presenter`）：離したときに「タップ」の働きをする。**0.5 秒押し続ける**と（Todo の完了の切り替えと同じ長さ）、離す前に「長押し」の働きをし、離しても何もしない。押しているあいだは、ふつうのセルと同じく枠が光る。設定を差し替えたときに押していたものは、何もしない。

#### 時計（clock）

| 項目 | 既定 | 内容 |
| --- | --- | --- |
| `format` | `15:04` | 時刻の行の書式 |
| `date_format` | `1月2日({wday})` | 日付の行の書式。`none` で出さない |
| `tz` | Brain のタイムゾーン | IANA の名前（`Asia/Tokyo`、`America/Los_Angeles`、`UTC` など）。知らない名前は誤り |

- **書式**：Go の `time.Format` の書き方。基準の日時「2006 年 1 月 2 日（月）15 時 04 分 05 秒」を、出したい形で書く。

  | 書き方 | 意味 | 例 |
  | --- | --- | --- |
  | `2006`、`06` | 年 | 2026、26 |
  | `01`、`1`、`Jan`、`January` | 月 | 10、10、Oct、October |
  | `02`、`2`、`_2` | 日 | 06、6、` 6` |
  | `15`、`03`、`3`、`PM` | 時 | 09、09、9、AM |
  | `04`、`4` | 分 | 05、5 |
  | `05`、`5`、`.000` | 秒、ミリ秒 | 07、7、.120 |
  | `Mon`、`Monday` | 曜日（英語） | Tue、Tuesday |
  | `{wday}` | 曜日（日本語 1 文字。lefthand の独自の書き方） | 火 |
  | `-07:00` | UTC からのずれ | +09:00 |

- **大きさ**：時刻の行は、セルに収まるいちばん大きな倍率（最大 10 倍）で描く。日付の行は最大 3 倍。
- **描き直しの間隔**：1 分に 1 回、分が変わった直後に描き直す。書式に秒（`05`、`5`、`.000` など）があるときだけ、1 秒に 1 回。
- **時刻を合わせていないとき**：Brain を起動してから一度も時刻を合わせていない（設定 GUI がつないでいない、NTP で合っていない）あいだは、時刻を橙色で描き、日付の行の代わりに「時刻未設定」と出す。合わせ方は README の「時刻合わせ」。

#### テキスト（text）

```yaml
"2,1": { widget: text, id: build, label: ビルド }
"0,2": { widget: text, id: note, span: [3, 1] }     # 横長のタイル
```

| 項目 | 内容 |
| --- | --- |
| `id` | 必須。中身の名前。英数字と `_ . -` の 32 文字まで。同じ id のセルをいくつ置いてもよい（どれも同じ中身） |

- **中身**：設定には書かない。PC から `brain-deck text <id> "..."`（プロトコルの `set_text`）で書き換え、Brain の `/var/lib/lefthand/text.json` に残る。デーモンや Brain を再起動しても残る。一度も書いていない id は、灰色で「未設定」と出る。
- **色**：`normal`（白）、`ok`（緑）、`error`（赤）、`warn`（黄）。

  | 種類 | ふつう | 有効期限が切れたとき |
  | --- | --- | --- |
  | normal | #ffffff | #6a7480 |
  | ok | #50d880 | #2e5a44 |
  | error | #ff5858 | #6a343a |
  | warn | #ffc030 | #6a582c |

- **有効期限**：書くときに `--ttl` を付けると、その時刻を過ぎたら、消さずに薄い色で描く。描き直しは、期限の時刻に 1 回だけ。
- **大きさ**：セルに収まるいちばん大きな倍率（最大 6 倍）で描く。セルの幅で折り返す（空白があれば空白で、なければ文字の境目で）。改行（`\n`）も使える。等倍でも入りきらなければ、入るところまで描いて「…」で切る。
- **長さ**：200 文字、8 行まで。
- **描き直し**：中身が変わったとき（`set_text`）と、期限が切れたときだけ。

#### Todo（todo）

```yaml
"0,0": { widget: todo, span: [2, 3], label: Todo }   # 縦長の一覧。1 ページに入るだけ並べる
"2,1": { widget: todo, rows: 3, span: [2, 1] }       # 1 ページ 3 行
```

| 項目 | 内容 |
| --- | --- |
| `rows` | 1 ページに並べる項目の数（1〜20）。省略すると、セルの高さに入るだけ並べる（1 行 52 ドット） |
| `page_reset` | ページを送ってから、触らずにこの時間がたつと 1 ページ目に戻る（`30s`、`2m` など。5 秒〜24 時間。既定 `1m`）。`off` で戻らない |

- **中身**：設定には書かない。設定 GUI の「Todo」タブか、PC の `brain-deck todo add "..."`（プロトコルの `todo_add` など）で書き換え、Brain の `/var/lib/lefthand/todo.json` に残る。Todo のセルを複数置くと、どれも同じ一覧を出す（ページは別々）。
- **並び**：未完了の項目を並べた順に出し、その下に完了した項目を出す。完了した項目は消さずに、薄い色（#6a7480）、塗った箱、取り消し線で描く。完了をまとめて消すのは、GUI の「完了した項目を消す」か `brain-deck todo clear-done`。
- **1 行**：左にチェックの箱、右に項目の文。文は 1 行で、入りきらなければ「…」で切る。文字の大きさは行の高さで決める（最大 3 倍）。
- **見出し**：`label` のあとに、残り（未完了）の件数を出す（「Todo 残り 3」。すべて完了なら「Todo すべて完了」）。`label` がなくても件数を出す。項目がなければ `label` だけ。
- **ページ送り**：入りきらないときは、セルの下に帯を出す。左の ▲ で前のページ、右の ▼ で次のページ、中央にページ番号（`1/3`）。押した瞬間にページを変える。これ以上送れない向きの矢印は暗くする。画面右の帯の ▲▼ は、本番の設定でレイヤーの切り替えに使っているので、Todo の帯は別に設けた。
- **完了の切り替え**：項目を **0.5 秒押し続ける**と、完了と未完了を切り替える（誤って触れても変わらない）。押しているあいだ、その行を黄色で塗る。0.5 秒より前に離すと、何もしない。切り替えると、項目は完了の側（下）か未完了の側へ移る。
- **押したときの見た目**：Todo のセルは押した位置で働くので、セル全体の枠は光らせず、押した行や矢印だけを黄色にする（`press_style` によらない）。
- **数**：上限はない。1 項目は 200 文字まで、改行は空白になる。
- **描き直し**：一覧が変わったとき、ページを送ったとき、押したとき・離したとき、`page_reset` で 1 ページ目に戻ったときだけ、そのセルを描き直す。実機で、2×3 のセル 1 つの描き直しは 10〜30 ms。

#### カレンダー（calendar）

```yaml
"0,0": { widget: calendar, span: [2, 3], label: 予定 }            # 縦長。今日の予定と次の予定
"2,1": { widget: calendar, span: [2, 1], calendars: [家], label: 家 } # 「家」のカレンダーだけ
"3,2": { widget: calendar, rows: 3, stale: 1h }                   # 1 ページ 3 行。1 時間で古いと出す
```

| 項目 | 内容 |
| --- | --- |
| `rows` | 1 ページに並べる行の数（1〜20）。省略すると、セルの高さに入るだけ並べる（1 行 52 ドット） |
| `page_reset` | ページを送ってから、触らずにこの時間がたつと、触っていないときのページに戻る（既定 `1m`、`off` で戻らない） |
| `stale` | 最終更新がこれより古ければ、最終更新の行を橙色にして「古い」と出す（`1m`〜`720h`。既定 `3h`） |
| `calendars` | 出すカレンダーの名前（brain-deck の calendars.yaml の `name`）。省略するとすべて |
| `follow` | 同じレイヤーの月の表示の `id`。そこで今日でない日を選んでいるあいだ、その日の予定を出す（下の「月の表示」） |

- **中身**：設定には書かない。PC の `brain-deck calendar sync`（プロトコルの `set_calendar`）が ICS の URL から取ってきて送り、Brain の `/var/lib/lefthand/calendar.json` に残る。繰り返しの予定とタイムゾーンは PC で解き、Brain には時刻の決まった予定と、日付だけの終日の予定が届く。
- **並び**：今日の予定を、終日の予定（今日をすべて含む予定も）、始まりの時刻の順に並べ、そのあとに、今日より先のいちばん早い予定を 1 つ（「次の予定」）並べる。今日の予定がなければ「今日の予定はありません」と出す。

  | 行 | 時刻の欄 | 見た目 |
  | --- | --- | --- |
  | 終日 | `終日` | ふつう |
  | 今の予定 | 終わりの時刻（`〜10:30`）。今日のうちに終わらなければ `今` | 行を青（#1e4a7c）で塗る |
  | これからの予定 | 始まりの時刻（`13:00`） | ふつう |
  | 終わった予定 | 始まりの時刻（前の日から続いた予定は `〜06:00`） | 薄い色（#6a7480）。左の帯も薄く |
  | 次の予定 | `明日 10:00`、`10/9(金) 10:00`、終日なら `明日`、`10/9(金)` | ふつう |

- **1 行**：左にカレンダーの色の帯、時刻の欄、予定の名前。名前は 1 行で、入りきらなければ「…」で切る。文字の大きさは行の高さとセルの幅で決める（最大 3 倍）。
- **最終更新**：いちばん下に「更新 10:35」（今日でなければ「更新 10/6 10:35」）を小さく出す。カレンダーが複数あれば、いちばん古いもの。次のときは橙色にする：`stale` より古い（「古い」を足す）、取得に失敗したカレンダーがある（「失敗 1」を足す。前の予定は残っている）、Brain の時刻を合わせていない（「時刻未設定」）。予定を一度も受け取っていなければ、中央に「予定を受け取っていません」と出す。
- **ページ送り**：Todo と同じく、入りきらないときはセルの下の ▲▼ で送る。触っていないときは、今の予定か、これからの予定がある最初のページを出す（朝の予定が多くても、今の予定が見える）。予定の行を押しても何もしない。
- **時刻**：「今日」と時刻は Brain のタイムゾーンで決める。Brain の時刻が遅れていると、今の予定がずれるので、`brain-deck calendar sync` は予定を送る前に時刻を合わせる。
- **描き直し**：予定が始まる時刻と終わる時刻、日付が変わる時刻、最終更新が古くなる時刻、予定を受け取ったとき、ページを送ったときだけ、そのセルを描き直す。実機で、2×3 のセルの描き直しは 20〜40 ms、予定の始まりと終わりの時刻から描き終わるまで 30 ms ほど。

#### 月の表示（month）

卓上カレンダーのように、1 か月分の日付を並べる。

```yaml
"0,0": { widget: month, id: cal, span: [2, 2] }                       # 2×2 のセル。週は日曜から
"2,0": { widget: calendar, follow: cal, span: [2, 2], label: 予定 }   # 月の表示で選んだ日の予定を出す
"0,0": { widget: month, span: [4, 2], week_start: monday, calendars: [仕事], page_reset: 30s }  # 横長、月曜から、仕事だけに印
```

| 項目 | 内容 |
| --- | --- |
| `id` | カレンダーのセルの `follow` で指す名前（英数字と `_ . -`、32 文字まで）。省略すると `month`。同じレイヤーに同じ `id` の月の表示を 2 つ置くと誤り |
| `week_start` | 週の始まり。`sunday`（既定）か `monday` |
| `page_reset` | 月を送るか日付を選んでから、触らずにこの時間がたつと、今月と今日に戻る（既定 `1m`、`off` で戻らない） |
| `calendars` | 予定の印（点）を付けるカレンダーの名前。省略するとすべて。祝日の赤は、これによらず出す |

- **並び**：上に年と月（「2026年10月」）、その下に曜日、7 列の日付（4〜6 週）。前後の月の日付は薄く出す。いちばん下の帯は ▲（前の月）、選んだ日の説明、▼（次の月）。
- **色**：今日は反転（白地に暗い数字）。選んだ日は黄色の枠。土曜は青、日曜と祝日は赤。
- **祝日**：PC の calendars.yaml で `holiday: true` を書いたカレンダー（README の「カレンダー」）の予定がある日を赤くする。そのカレンダーには点を付けない。祝日の名前は、日付を選んだときに帯と、`follow` のカレンダーのセルに出る。
- **予定の印**：予定のある日の数字の下に、カレンダーの色の点を出す。1 日にカレンダー 1 つにつき点 1 つ（予定の数ではない）で、カレンダーの順に並べる。4 つ以上のカレンダーに予定がある日は、2 つの色と、灰色の点（ほかにもある）。何日も続く予定は毎日に付ける。0 時ちょうどに終わる予定は、次の日には付けない。
- **帯の説明**：選んだ日（選んでいなければ今日）の日付、祝日の名前、予定の数（「10/12(月) スポーツの日」「10/6(火) 予定5」「予定なし」）。送られてきた範囲の外の日は「範囲外」、予定を一度も受け取っていなければ「予定未受信」。
- **操作**：▲▼ で前後の月に送る（前後 24 か月まで）。日付をタップすると、その日を選ぶ（前後の月の薄い日付も選べる）。帯の中央をタップすると、すぐに今月と今日に戻る。どれも `page_reset` のあいだ触らなければ、今月と今日に戻る。
- **選んだ日の予定（follow）**：同じレイヤーの、`follow: <id>` を書いたカレンダーのセルは、今日でない日を選んでいるあいだ、その日の予定（終日、始まりの時刻の順）を出し、見出しに日付を足す（「予定 10/17(土)」）。過ぎた日の予定は薄く出す。今日を選んでいるとき、選んでいないときは、ふだんどおり今日の予定と次の予定。`follow` の `id` の月の表示が同じレイヤーにないと誤り（下のレイヤーの月の表示は指せない）。
- **見出しの右**：Brain の時刻を合わせていなければ「時刻未設定」（年と月も橙色）。出している月が送られてきた範囲から外れていれば「範囲外」、一部だけなら「一部範囲外」。
- **大きさ**：2×2 のセル以上を前提にしている。それより小さいと、`-check` と設定 GUI で警告する（誤りではない）。数字の大きさは、セルの高さと幅で決める（2×2 で 2 倍）。
- **描き直し**：日付の変わり目、予定を受け取ったとき、月を送ったとき、日付を選んだとき、今月に戻るときだけ描き直す。実機で、月を送ると 20〜55 ms、日付を選ぶと月の表示と `follow` のセルで 40〜70 ms。1000 件の予定を受け取ったときは 0.8〜1.3 秒（1 回だけ）。押した位置は予定を見ずに解く（入力の処理で 0.3 ms）ので、描いている最中でもキーは待たない。
- **例**：[config/month-example.yaml](../config/month-example.yaml)（メニューの「月」「月(横)」）。

#### 天気（weather）

今日の天気（幅があれば明日も）を出す。予報は PC の `brain-deck weather sync` が、天気予報 API（livedoor 天気互換。データの元は気象庁）から取ってきて送る（README の「天気」）。

```yaml
"0,0": { widget: weather, span: [2, 2] }              # 今日と明日。アイコンの下に天気と気温、時間帯の見出しつきの降水確率
"2,0": { widget: weather, span: [2, 1] }              # 今日と明日。アイコンの右に天気と気温
"2,1": { widget: weather, label: 天気, stale: 2h }    # 今日だけ。2 時間で古いと出す
"0,0": { widget: weather, span: [4, 1], key: F5 }     # 低いセルでは 1 行。タップで F5 を送る
```

| 項目 | 内容 |
| --- | --- |
| `stale` | 最終更新がこれより古ければ、最終更新の行を橙色にして「古い」と出す（`1m`〜`720h`。既定 `3h`。sync を 1 時間ごとにするなら、2〜3 回逃したら分かる） |
| `key`、`layer_*` など | タップしたときの動き（省略可）。天気のセルは押した位置を使わないので、時計と同じく書ける |

- **列**：見出しの下の範囲の幅が 288 ドット以上（4×3 の格子の 2×1 以上）なら、今日と明日を 2 列に並べ、あいだに線を引く。それより狭ければ今日だけ。
- **列の中**：見出し（「今日 10/10(土)」。入らなければ「今日」）、天気のアイコン、天気の文（「晴時々曇」）、最高と最低の気温（「26°/16°」。最高は橙、最低は青）、6 時間ごとの降水確率（0〜6、6〜12、12〜18、18〜24 時）。
  - 列の高さが 48 ドットより低い：1 行に、アイコン、見出し、天気、気温（入らなければ見出しを省き、それでも入らなければ天気の文を切る）
  - 縦長（見出しと降水確率のあいだが、幅の 3/4 以上）：アイコンの下に天気と気温
  - それ以外：アイコンの右に天気と気温
  - 降水確率は、列の高さが 96 ドット以上で出し、150 ドット以上なら時間帯の見出しも出す。50% 以上は濃い青、20% 以上は薄い青
  - 文字の倍率は 3 倍まで（幅と高さで決める）。列の幅が 240 ドット以上で高さが 200 ドット以上なら、見出しと降水確率も 2 倍
- **取れない値**：気温と降水確率で API が null や「--%」を返したもの（今日の最低気温、17 時の発表のあとの今日の最高気温、過ぎた時間帯の降水確率）は「--」。今日の、Brain の時刻で過ぎた時間帯の降水確率は薄く出す。
- **今日の決め方**：Brain の日付と同じ日付の予報を今日とする。0 時〜5 時は、API が前の日の発表の「明日」を今日として返すので、そのまま今日に出る（発表の時刻に日付が付く）。予報のない日は「データなし」。
- **最終更新**：いちばん下に「更新 9:05 5時発表 出典:気象庁」を小さく出す（今日でなければ日付を付ける）。次のときは橙色にする：`stale` より古い（「古い」を足す）、最後の取得に失敗した（「失敗」を足す。前の予報は残っている）、Brain の時刻を合わせていない（「時刻未設定」）。幅が足りなければ、発表の時刻、「出典:」の順に省く。最終更新の行を置くと予報が 1 行も入らないセルでは、最終更新の行を出さない。予報を一度も受け取っていなければ、中央に「天気を受け取っていません」（失敗だけを受け取っていれば「天気を取得できません」）。
- **アイコン**：アイコンの箱は、列の大きさだけで決める（縦横 3:2。天気の文の長さでは変わらない）。PC の brain-deck は、この大きさでアイコンを作って送る。Brain にまだその大きさのアイコンがなければ、アイコンなしで描く（セルの大きさを変えたら、保存してから `brain-deck weather sync`）。アイコンはセルの背景（塗りや背景画像）に、透明度で重ねる。
- **描き直し**：予報やアイコンを受け取ったとき、6 時間の区切り（0、6、12、18 時）、日付の変わり目、古くなる時刻だけ描き直す。
- **例**：[config/weather-example.yaml](../config/weather-example.yaml)（メニューの「天気」「天気(小)」）。

#### グラフ（graph）

PC から送った値を、折れ線か棒で描く。値は PC の `brain-deck graph <id> <値>` で 1 つずつ足す（README の「グラフ」）。CPU の使用率、メモリ、温度などを、定期的に送る使い方を考えている（[contrib/graph/linux-stats.sh](../contrib/graph/linux-stats.sh)）。

```yaml
"0,0": { widget: graph, id: cpu, label: CPU, unit: "%", min: 0, max: 100, span: [2, 1] }   # 0〜100 の折れ線
"2,0": { widget: graph, id: mem, label: メモリ, unit: "%", min: 0, max: 100, chart: bar }  # 棒
"0,1": { widget: graph, id: temp, label: 温度, unit: ℃, points: 120, stale: 2m }          # 範囲は値から決める
"3,1": { widget: graph, id: load, decimals: 2, key: F5 }                                 # タップで F5 を送る
```

| 項目 | 既定 | 内容 |
| --- | --- | --- |
| `id` | （必須） | 値の名前（`brain-deck graph <id> <値>` の id）。英数字と `_ . -` の 32 文字まで。同じ id のセルは同じ値を出す |
| `unit` | なし | 値のあとに付ける単位（`%`、`℃`、`MB` など。8 文字まで。空白も含めてそのまま付ける） |
| `min`、`max` | 値から決める | 縦の範囲。書かなければ、描いている値の最小と最大（棒では 0 も含める）。範囲の外の値は、上か下の端に描く。両方を書くときは `min` < `max` |
| `chart` | `line` | `line`（折れ線）か `bar`（棒） |
| `points` | `60` | 描く値の数（2〜120）。新しいものから描き、いちばん新しい値を右端にする。足りないうちは右に寄せる |
| `decimals` | 値で決める | 小数点以下の桁数（0〜6）。書かなければ、100 以上は 0 桁、10 以上は 1 桁、それより小さければ 2 桁で、末尾の 0 を省く（`27.6`、`1.13`） |
| `stale` | `5m` | いちばん新しい値がこれより古ければ、値と線を薄くし、値の下に「古い 15:04」（日付が違えば「古い 10/9 15:04」）を橙色で出す（`1m`〜`720h`） |
| `key`、`layer_*` など | | タップしたときの動き（省略可）。グラフのセルは押した位置を使わないので、時計と同じく書ける |

- **配置**：見出しの下に、いちばん新しい値を大きく（6 倍まで）出し、その下に線を描く。横長のセル（幅が高さの 2 倍以上）では、左の 2/5 に値、右に線。線を描く範囲の高さが 16 ドットより低ければ、値だけを出す。範囲の高さが 36 ドット以上あれば、左に上と下の値（範囲）を小さく出し、上と下に細い線を引く。
- **横の軸**：値の時刻は見ず、届いた順に等しい間隔で並べる（送る側の間隔がまちまちでも、形は崩れない）。時刻が分かるのは、いちばん新しい値の「古い」の表示だけ。
- **値がまだないとき**：「未受信」。
- **値の数字**：Go と設定 GUI で同じ文字にするため、四捨五入は「10 の桁数乗を掛け、0.5 を足して切り捨てる」で行う（ちょうど半分は、絶対値の大きいほうに丸める）。
- **保存**：値は `/var/lib/lefthand/graph.json`（id ごとに新しい 120 個、32 個の id まで）。値を受け取るたびには SD カードに書かず、**前に書いてから 5 分たつまで待ってまとめて書く**（しばらく来ていなかったときは 10 秒待つ）。デーモンが終わるときは、まだ書いていない値を書く。電源が急に切れると、最後の最大 5 分ぶんがなくなる。
- **描き直し**：値を受け取ったときと、古くなる時刻だけ。
- **例**：[config/graph-example.yaml](../config/graph-example.yaml)（メニューの「グラフ」）。

#### トラックパッド（trackpad）

```yaml
"0,0": { widget: trackpad, span: [3, 4], label: トラックパッド }                 # 値は既定値
"0,0": { widget: trackpad, span: [3, 3], speed: 1.5, accel: 0.5, scroll_width: 0 } # 速く、加速を弱く、帯なし
```

セルの中で指を動かすとカーソルが動く。短いタップで左クリック、タップしてすぐ触れて動かすとドラッグ、右端の帯をなぞると縦のスクロール。
操作の説明は README の「マウスとトラックパッド」。項目はどれも省略でき、省略すると既定値。

| 項目 | 範囲 | 既定 | 内容 |
| --- | --- | --- | --- |
| `speed` | 0.05〜20 | 1.2 | 感度。画面の 1 ドットの動きを、マウスの何カウントにするか（ゆっくり動かしたとき） |
| `accel` | 0〜10 | 2.0 | 加速。速さ v（ドット/秒）のとき speed × (1 + accel × min(v/1000, 3)) 倍。0 で加速しない |
| `scroll_width` | 0〜400 | 96 | 右端のスクロールの帯の幅（ドット）。セルの右端から数える。0 で帯なし |
| `scroll_direction` | `natural`、`traditional` | `natural` | natural は指を下へ動かすと中身が下へ動く（上へスクロール。スマホと同じ）。traditional はホイールと同じ（指を下へ＝下へスクロール） |
| `scroll_step` | 2〜400 | 24 | ホイール 1 段に当たる指の動き（ドット） |
| `settle_ms` | 0〜500 | 80 | 触れてから、この時間のサンプルを捨てる（触れた直後の跳ねと、押し始めの流れ） |
| `smooth` | 1〜10 | 3 | 最後のこの数のサンプルの平均を使う |
| `deadzone` | 0〜50 | 1.5 | 平均の位置が、この距離（ドット）より動かなければ無視する。止めているときの揺れと、動き始めの小さな動き |
| `min_pressure` | 0〜4095 | 500 | 押す強さ（ABS_PRESSURE）がこれより小さいサンプルを捨てる。そういうサンプルしかないタッチは、なかったことにする。0 で見ない |
| `tap_ms` | 30〜1000 | 250 | これより短く触れて離せばタップ |
| `tap_move` | 0〜200 | 8 | タップとみなす動きの上限（ドット。ブレ対策を通した位置で、触れた位置からいちばん離れた距離） |
| `drag_ms` | 0〜1000 | 300 | タップで離してから、次のタッチを待つ時間。そのあいだに触れて動かすとドラッグ、すぐ離すとダブルクリック。過ぎるとボタンを離す（クリック）。左ボタンは、離してから 110 ms あとに押す（着地の跳ねを待つ）。0 にすると、タップしたら 110 ms あとにクリックする |
| `long_press` | `none`、`right` | `none` | right なら、0.6 秒動かさずに押すと右クリック |

- **判定のしかた**：触れた位置がトラックパッドのセルなら、離すまでのサンプルをすべてトラックパッドで使う（指がセルの外に出ても動かし続ける）。触れた位置が帯なら、そのタッチはスクロールだけ（カーソルは動かさない）。
- **離す直前**：最後の 2 つのサンプルは遅らせて使い、離したときに捨てる（離す瞬間の跳ね）。
- **止めた指の流れ**：平均の位置が `deadzone` の内側にあるあいだは、基準の位置を 6 ドット/秒まで指に寄せる（送らない）。押す強さが変わって位置がゆっくり流れても、カーソルを動かさない。
- **なかったことにするタッチ**：押す強さが `min_pressure` 以上のサンプルが 1 つもないタッチ（離した直後の弱い接触など）。タップの待ちなどは、そのまま続ける。
- **一瞬離れたとき**：なぞる、帯のスクロール、ドラッグの途中で指が離れ、150 ms のうちに触れ直したら、同じタッチの続きにする（ドラッグなら左ボタンを離さない。帯ならスクロールのまま）。位置は触れ直したところから測り直す（離れていたあいだの動きは送らない）。触れ直したときは、`settle_ms` の代わりに 30 ms だけ捨てる。
- **着地の跳ね**：タップで離してから 110 ms のうちに触れ直したら、同じタッチの続きにする（タップの長さは最初に触れたときから測る）。タップのあとすぐ動かしても、ドラッグやダブルクリックにならない。
- **帯のタップ**：帯ではタップしてもクリックしない（なぞる途中の切れ目の短いかけらが、タップに見えるため）。帯かどうかは、押す強さの足りる最初のサンプルの位置で決める。
- **ほかのセルに触れたとき**：タップのあとの待ち（`drag_ms`）のあいだにほかのセルに触れたら、待たずにクリックを終える。
- **レイヤーの切り替え、設定の再読み込み**：ドラッグやタップの待ちをやめ、ボタンを離す。そのタッチは、指を離すまで何もしない。
- **描き直し**：見出しと帯は、レイヤーを描くときに描くだけ。触っているあいだは描き直さない。押したときの枠も出さない。
- **マウスがオフのとき**：USB がキーボードだけの形のあいだは、セルの中央に「マウスはオフ」と出し、触っても何もしない（`usb_mode` で切り替える）。
- **書けない項目**：`key`、`layer_*`、`mouse`（タップはクリックになるため）。`format` など、ほかのウィジェットの項目。

##### 調整の余地

- **タップしてからのドラッグ**：記録では、タップしてから触れ直すまで 0.4〜0.85 秒あいていた。`drag_ms` をそこまで長くすると、クリックのボタンを離すのがその分遅れ、クリックしてすぐカーソルを動かすとドラッグになる（ファイルを動かしてしまうなど）。そのため 300 ms にした。ドラッグは、すぐに触れ直すか、本体のキーに `mouse: left` を割り当てて押さえたまま動かす。使ってみて、ドラッグのほうが多ければ `drag_ms` を 500〜900 にする。
- **帯の位置**：記録では、帯の手前をなぞっていた。キャリブレーションのずれか、見え方のずれかは、記録からは分からない。
- **帯の外の縦のなぞり**：帯の外を縦に速くなぞると、途中で切れた短いかけらがタップに見え、まれにクリックやドラッグになる（scroll の記録をそのまま再生すると、20 回のタッチで、クリック 1、ドラッグ 2）。
- **感度と加速**：PC の画面の大きさと、OS の加速によって感じ方が変わる。記録からは決めきれないので、使ってみて `speed`、`accel` を変える。

#### 電池（battery）

```yaml
"2,0": { widget: battery, label: 電池 }
"3,2": { widget: battery, key: F5 }        # タップでキーを送る
```

電池の残り（%）を大きく、その下に「充電中」「USB 給電」「電池」のどれかを出し、いちばん下に残りの帯を出す。項目はない（`label` とタップの動きだけ）。

- **読み方**：`/sys/class/power_supply` に電池があれば、その `capacity` と `status`。PW-SH2（Brainux のカーネル）にはないので、i.MX28 の LRADC（IIO の `mxs-lradc-adc`）の ch7（電池の電圧）と ch15（USB の 5V）を読む。30 秒ごとに読み、電圧は 5 回（2 分半）の移動平均を取る。
- **見積もり（PW-SH2）**：残りは Li-ion の電圧の目安の表から見積もる（3.40 V で 0%、3.70 V で 33%、4.00 V で 85%、4.15 V 以上で 100%）。USB の 5V があって 4.15 V より低ければ「充電中」、4.15 V 以上なら「USB 給電」とする。充電は外付けの IC が行い、その状態はソフトウェアから読めないため。USB につないでいるあいだは電圧が高めに出るので、残りも多めに出る。
- **色**：充電中は緑。そうでなければ 30% 以下で黄、15% 以下で赤。
- **読めないとき**：「--%」「電池を読めません」を灰色で出す。

#### ストップウォッチ（stopwatch）

```yaml
"0,0": { widget: stopwatch, span: [2, 1], label: ストップウォッチ }
"2,0": { widget: stopwatch, id: meeting, label: 会議 }   # 別のストップウォッチ
```

- **タップ**：止まっていれば始め、動いていれば止める。**長押し**：0 に戻して止める。
- **表示**：1 時間までは「分:秒」、それより長ければ「時:分:秒」。下に「計測中」「停止中」（黄）、0 のときは「タップで開始」（灰）。動いているあいだは 1 秒ごとに描き直す。
- **保存**：`/var/lib/lefthand/widgets.json`。動いているあいだは始めた時刻を覚えるので、デーモンを再起動しても数え続ける。**Brain を再起動すると止まる**（Brain には RTC がなく、起動直後の時刻が当てにならないため）。デーモンが終了の処理をしたとき（電源を切る、再起動するなど）は、その時点までの時間が残る。電池が切れたときなどは、最後に始めた時点までになる。
- **時刻合わせ**：設定 GUI や brain-deck が Brain の時刻を動かしても、経過時間は変わらない（始めた時刻も同じだけ動かす）。

#### ポモドーロ（pomodoro）

```yaml
"0,1": { widget: pomodoro, span: [2, 2], label: ポモドーロ }               # 作業 25 分、休憩 5 分
"2,1": { widget: pomodoro, id: deep, work: 50m, break: 10m, label: 集中 }
```

| 項目 | 既定 | 内容 |
| --- | --- | --- |
| `work` | `25m` | 作業の時間。1 分〜4 時間、秒の単位まで |
| `break` | `5m` | 休憩の時間。1 分〜4 時間、秒の単位まで |

- **タップ**：まだ始めていない、または一時停止なら始める（続ける）。動いていれば一時停止する。点滅しているあいだのタップは、点滅を止めるだけ。**長押し**：最初（作業の始まり、終えた回数 0）に戻す。
- **動き**：作業と休憩をくり返す。残りを大きく（作業は赤、休憩は緑）、下に「作業中」「休憩中」と終えた作業の回数（「2回」）を出す。一時停止は灰色で「一時停止 作業」。
- **知らせ方**：作業と休憩が切り替わったら、**セルを 15 秒、0.5 秒ごとに点滅させる**（段階の色で塗る）。画面が暗ければ明るくする（下の「自動減光」）。音は出さない（Brain のブザーは、今のカーネルとデバイスツリーでは使えるデバイスになっていない。2026-10-09 に確かめた）。
- **時間を変えたとき**：始めたときの `work` と `break` で動き続ける。新しい時間は、長押しで最初に戻してから始めると使う。
- **保存**：ストップウォッチと同じ（`widgets.json`。Brain を再起動すると一時停止になる）。

#### カウンター（counter）

```yaml
"3,0": { widget: counter, label: カウンター }
"2,1": { widget: counter, id: coffee, label: コーヒー }
```

- **タップ**：1 増やす。**長押し**：0 に戻す。値は 0〜999999999。
- **保存**：`widgets.json`。デーモンや Brain を再起動しても残る。

#### QR コード（qr）

```yaml
"0,0": { widget: qr, id: share, span: [2, 3], label: 共有 }
```

| 項目 | 内容 |
| --- | --- |
| `id` | 必須。中身の名前（テキストと同じ形） |

- **中身**：テキストのタイルと同じ仕組み。設定には書かず、PC から `brain-deck qr <id> "https://..."`（プロトコルの `set_qr`）で送り、Brain の `/var/lib/lefthand/qr.json` に残る。`--ttl` で有効期限を付けられ、過ぎると消さずに薄い色（灰色の地に濃い灰色）で描く。一度も送っていなければ「未設定」。
- **長さ**：UTF-8 で 400 バイトまで。改行とタブも使える。ASCII 以外の文字を含むときは、UTF-8 であることを示す ECI を付ける。
- **符号**：誤り訂正のレベル M（同じ大きさに収まるなら上げる）、バージョンは収まるいちばん小さいもの。
- **大きさ**：1 升を 2 ドット以上の整数倍にし、周りに白い余白を 4 升（入らなければ 2 升）付けて、セルの中央に置く。入らなければ「QR が入りません」と出すので、`span` でセルを大きくする。4×3 の格子の 2×3 のセルなら、400 バイトでも入る。
- **タップしたときの動き**：`key` などを書ける。

#### 在席ランプ（presence）

```yaml
"2,0": { widget: presence, span: [2, 2] }                      # 在席、集中、会議中、休憩
"3,1": { widget: presence, id: door, states: [{name: 在室, color: "#40c070"}, {name: 不在, color: "#606870"}] }
```

| 項目 | 内容 |
| --- | --- |
| `states` | 状態の並び（1〜12 個）。`name` は 1〜16 文字（前後の空白、制御文字は不可）、`color` は `#rrggbb`（省略すると順に決まった色）。省略すると、在席（#40c070）、集中（#ff5858）、会議中（#ff8020）、休憩（#4f9dff） |

- **表示**：セル全体を今の状態の色で塗り、状態の名前を大きく出す（文字は、色の明るさで黒か白）。まだ一度も変えていなければ、最初の状態。ほかのセルの状態の名前にした（同じ id で、状態の並びが違う）ときは、名前を灰色の地で出す。
- **タップ**：次の状態（最後の次は最初）。**長押し**：前の状態。
- **PC から**：`brain-deck presence 会議中`、`brain-deck presence next --id door`（プロトコルの `set_presence`）。
- **保存**：`widgets.json`（状態の名前）。再起動しても残る。

#### プレゼン用タイマー（presenter）

発表の持ち時間を計る。残り時間を大きく、経過時間を小さく出し、いちばん下に進み具合の帯を出す。

```yaml
"0,0": { widget: presenter, id: talk, duration: 20m, label: 発表 20分, span: [2, 2] }   # 色は既定（残り 5 分で黄、1 分で赤）
"0,0": { widget: presenter, id: lt, duration: 5m, span: [2, 2],                         # LT：残り 1 分で黄、30 秒で赤
         colors: [{ remaining: 1m, color: "#ffc030" }, { remaining: 30s, color: "#ff5858" }] }
```

| 項目 | 既定 | 内容 |
| --- | --- | --- |
| `id` | `presenter` | 状態の名前。同じ id のセルは同じタイマーを出す |
| `duration` | `10m` | 持ち時間。10 秒〜24 時間、秒の単位まで |
| `colors` | 残り 5 分で黄、1 分で赤 | 色の区切り（6 つまで）。`remaining`（残りがこの時間以下になったら。秒の単位まで）と `color`（`#rrggbb`）。書いた順によらず、残りの短い区切りが優先する。`colors: []` なら色を変えない |

- **タップ**：止まっていれば始め（続け）、動いていれば一時停止する。**長押し**（0.5 秒）：0 に戻して止める。タップしたときのキーなどは書けない。
- **表示**：残り時間（秒は切り上げ。1 時間以上なら「時:分:秒」）。下に「経過 3:12」、止めているあいだは「一時停止 経過 3:12」（灰色）、まだ始めていなければ「タップで開始」。
- **時間を過ぎたら**：「+0:12」のように超えた時間を赤で出し、下に「時間切れ 経過 20:12」。動いているあいだは、**セルを 0.5 秒ごとに赤く点滅させる**（一時停止すると止まる）。
- **自動減光**：どれかのプレゼン用タイマーが動いているあいだは、画面を暗くも消しもしない（暗ければ明るくする）。止めたら、そこから時間を数え直す。
- **スライド送り**：同じレイヤーに、`PAGEUP`、`PAGEDOWN`（プレゼンター用のリモコンと同じ）や、画面右の帯の `left`、`right` に `LEFT`、`RIGHT` を割り当てると、タイマーを見ながらスライドを送れる。
- **保存**：ストップウォッチと同じ（`widgets.json` の `presenter`。デーモンを再起動しても数え続け、Brain を再起動すると止まる）。持ち時間はセルの設定なので、動いているあいだに `duration` を変えると、残り時間もすぐ変わる。
- **例**：[config/presenter-example.yaml](../config/presenter-example.yaml)（メニューの「発表」「LT」）。

### 背景画像（background）

```yaml
layers:
  - name: base
    touch:
      cols: 4
      rows: 3
      background: 7f8f231d4a49bfee                                   # 壁紙
      cells:
        "0,0": { key: LGUI+S, label: 保存, background: b18c7e1fecc29a03 } # セルの背景
        "2,0": { widget: clock, span: [2, 1], background: c1ee527da7f58e93 }
```

| 書く場所 | 内容 |
| --- | --- |
| レイヤーの `touch.background` | 壁紙。画面全体（800×480）の画像。セルの隙間と、背景画像のないセルの中に見える |
| セルの `background` | セルの背景。セルの枠の内側（セルの範囲から 4 ドット内側。4×3 なら 192×152、span なら覆う範囲全体）の画像 |

- **値**：背景画像の id。画像ファイル（`/var/lib/lefthand/images/<id>.565`）の SHA-256 の先頭 16 文字（16 進の小文字）。ふつうは設定 GUI が書く。形が違えば誤り。
- **ファイルの形**：先頭 8 バイトが `LHI1`、幅、高さ（リトルエンディアンの uint16）。続けて左上から行の順に、1 画素 2 バイトの RGB565（リトルエンディアン）。1 枚 800×480 まで（各辺 800 まで、384,000 画素まで）。
- **使える場所**：タッチのセルだけ（キー、ウィジェット、span のどのセルでも）。本体キーとソフトキーには書けない（誤り）。割り当てのないセルには置けない（壁紙は見える）。
- **重ね方**：画面の黒 → 壁紙 → セルの塗り（壁紙があれば壁紙のまま）→ セルの背景画像。そのうえに枠とラベル。
- **縁取り**：壁紙かセルの画像があるセルでは、文字（ラベル、送信キー、ウィジェットの文字）に、文字の点を上下左右と斜めに 1 ドット広げた黒い縁取りを付ける。縁取りもセルの内側（textMargin）からはみ出さない。gui/src/preview.ts と同じ描き方。
- **押したとき**：`border` は画像の上に二重の枠を描き、離すと枠の帯だけを画像で描き直す。`fill` は黄色で塗りつぶす（そのあいだ画像と縁取りは出ない）。
- **壁紙の透過**：セルと同じ。上から見て、格子の大きさが同じあいだのレイヤーで、いちばん上にある `touch.background` を使う。cols と rows を省略した touch（`touch: { background: ... }`）は、base と同じ大きさの、セルのない格子になる。
- **ない画像、大きさの違う画像**：誤りにはしない（設定は使える）。ない画像は背景なしで描き、大きさが違う画像は中央に置いて、はみ出す分は切る。どちらも `lefthand -check`（`-data-dir` か `-render-images` の画像で調べる）、起動時、validate と set_config の warnings に出る。

### 動き方の細かい決まり

- **押したまま切り替えたとき**：キーは、押したときの割り当てで離す。たとえば edit で Ctrl+C を押したまま edit を抜けても、離したときに Ctrl+C を離す。
- **layer_hold**：押したキーを離すと、そのキーで重ねたレイヤーだけを外す。ほかの重なりはそのまま。
- **layer_toggle**：そのレイヤーが layer_toggle か layer_to で重なっていれば外し、なければ重ねる。上のレイヤーで同じキーを書かなければ、透過して base の layer_toggle が働くので、同じキーで戻れる。
- **layer_oneshot**：layer_* 以外の入力を押したとき（割り当てのないキーを含む）に、押したキーの割り当てを決めてから外れる。
- **layer_to**：重なりを全部外してから、行き先を重ねる。layer_hold で押しているキーを離しても、もう何も外れない。
- **オートリピート**：無視する。リピートは PC 側に任せる。端末モードのあいだだけは、Brain のカーネルのオートリピートで文字を繰り返す。

## 画面の表示

- **右上の札**：今のレイヤーの label を出す。色で入り方がわかる。
- **色**：base だけのときは青、layer_toggle か layer_to で入ったとき（離しても戻らない）は緑、layer_hold か layer_oneshot で入ったとき（一時的）は橙。セルの枠も同じ色になる。
- **描き直し**：レイヤーが変わると、画面全体を描き直す。描画は別のスレッドで行い、キー入力の処理を待たせない。

### 押しているセルの見せ方（display.press_style）

```yaml
display:
  press_style: border   # border（既定）か fill
```

| 値 | 押しているあいだの見た目 | 描き直す範囲 |
| --- | --- | --- |
| `border` | セルの内側に二重の枠を描く。外側 2 ドットが黒、内側 5 ドットが黄色（#ffd040）。セルの中身とラベルはそのまま | 枠の帯だけ |
| `fill` | セル全体を黄色で塗りつぶし、ラベルを黒で描く（以前の見せ方） | セル全体 |

- **既定**：書かないと `border`。それ以外の値は誤り。
- **二重の枠の理由**：外側の暗い線があるので、明るい色や画像の背景の上でも枠の縁が分かる。枠はラベルの余白（8 ドット）より細いので、ラベルには重ならない。
- **離したとき**：ふだんの枠（2 ドット、レイヤーの入り方の色）に戻す。
- **割り当てのないセル**：押しても見た目は変わらない。
- **反映**：`display` のほかの項目と違い、設定 GUI から保存すれば、デーモンを再起動せずにすぐ反映する。
- **確かめ方**：`lefthand -render-png out.png -render-pressed "0,0" config.yaml` で押した画面を書き出せる。`-render-press-style fill` で、設定と違う見せ方も試せる。

## 自動減光（backlight）

しばらく触らなければ画面（バックライト）を暗くし、さらに時間がたったら消す。書かなければ、今までどおり減光しない。

```yaml
backlight:
  dim_after: 1m       # 触らずにこの時間がたったら暗くする。off か省略で暗くしない
  dim_level: 1        # 暗くしたときの明るさ（既定 1）
  off_after: 5m       # 触らずにこの時間がたったら消す（明るさ 0）。off か省略で消さない
  level: 7            # ふだんの明るさ。省略すると起動したときの明るさ
  wake_on_key: true   # 本体キーでも明るくする（既定 true）
  in_terminal: false  # 端末モードのあいだも暗くする（既定 false）
  device: /sys/class/backlight/backlight@0   # 省略すると最初のもの
```

| 項目 | 範囲 | 内容 |
| --- | --- | --- |
| `dim_after`、`off_after` | 5s〜24h、off | 最後に触ってからの時間。両方書くなら `off_after` を長くする。`dim_after` だけなら暗くするだけ、`off_after` だけなら暗くせずに消す |
| `level`、`dim_level` | 0〜max_brightness | PW-SH2 は 0〜7（PWM の 255 分率で 0、4、8、16、32、64、128、255）。max_brightness より大きければ、max_brightness にする（ログに出す）。`level` は 1 以上 |
| `wake_on_key` | 真偽 | true なら、本体キーを押すと明るくし、時間を数え直す。false なら、キーは明るさに関係しない |
| `in_terminal` | 真偽 | false なら、端末モードのあいだは暗くしない（抜けたら数え直す） |

- **暗いときのタッチ**：暗くしたか消したあとのタッチは、**明るくするだけで、そのタッチではセルもソフトキーも押さない**（誤って押さないため）。離すまでのサンプルもすべて捨てる。次のタッチからふつうに働く。
- **暗いときのキー**：本体キーは、暗いときもそのまま PC に送る（文字の入力を止めない）。
- **触れているあいだ**：指が触れているあいだ（トラックパッドで長く動かしているときなど）は暗くしない。離したときから数える。
- **プレゼン用タイマー**：どれかが動いているあいだは暗くしない（止めたときから数え直す）。
- **ほかに明るくするとき**：ポモドーロの作業と休憩が切り替わったとき。設定 GUI から設定を保存したとき（新しい設定ですぐ数え直す）。
- **反映**：設定 GUI から保存すれば、再起動せずに反映する（`backlight` は GUI では編集しないが、ファイルを直接編集したあと GUI で保存しても残る）。
- **終わるとき**：起動したときの明るさに戻す。強制終了などで戻せなかったときは、`lefthand -restore-console`（サービスの ExecStopPost）が `/run/lefthand-backlight` に残した明るさに戻す。
- **状態を見る**：`brain-deck status` の「画面の明るさ」、プロトコルの `get_status` の `backlight`。

## 読み込み時の検証

次のものは誤りとして、デーモンを起動しない。

| 誤り | 例 |
| --- | --- |
| 存在しないレイヤーの参照 | `layer_hold: nope` |
| base に戻れないレイヤー | layer_toggle か layer_to で入るのに、戻る手段がない。layer_to どうしで行き来するだけで base に戻れない輪も含む |
| base への layer_toggle | base は外せないので、layer_to を使う |
| レイヤー名の重複・名前なし | |
| 割り当ての書き方 | key と layer_* を両方書いた、どれも書いていない、知らない項目 |
| 知らないキー名 | `KEY_NOPE`、`LCTRL+NOPE` |
| 格子の外のセル、同じセルの重複 | 4x3 の格子に `"4,0"` |
| span がはみ出す、重なる | 4x3 の格子の `"3,0"` に `span: [2, 1]` |
| 背景画像の書き方 | id が 16 文字の 16 進でない、本体キーやソフトキーの `background` |
| ウィジェットの書き方 | 知らない `widget`、知らない `tz`、widget なしの `format`、本体キーやソフトキーの `widget`・`span`、ウィジェットに `key: none`、`todo`、`calendar`、`month`、`trackpad` に `key` や `layer_*` や `mouse`、`week_start` が `sunday`・`monday` 以外、`follow` の `id` の月の表示が同じレイヤーにない、同じレイヤーの月の表示の `id` の重なり、`rows` が 1〜20 の外、`page_reset` や `stale` の時間の誤り、トラックパッドの項目の範囲の外、トラックパッド以外のトラックパッドの項目 |
| マウスの操作、メディアキー | 知らない `mouse` の値、知らない `media` の値、知らない `usb_mode` の値 |
| 新しいウィジェット | `stopwatch`、`pomodoro`、`counter`、`presence` に `key` などのタップの動き、`qr` に `id` がない、`work`・`break` の時間の誤り、`states` の数・名前・色の誤り、名前の重なり |
| 自動減光 | `dim_after`・`off_after` の時間の誤り、`off_after` が `dim_after` より短い、`level` が 0、`device` が /sys/class/backlight の外（場所は `/backlight`） |
| 定義していないソフトキー | soft_areas にない名前を soft_keys に書いた |
| base の格子がない | touch があるのに、base に cols/rows がない |
| 旧形式との混在 | layers と、トップレベルの keys（または touch.cells）を両方書いた |

**base に戻る手段**とみなすのは、そのレイヤーを base の上に重ねたときに押せる（透過も含む）、次のいずれか。

- `layer_to: base`
- そのレイヤー自身の `layer_toggle`
- base に戻れるレイヤーへの `layer_to`
- `layer_hold` か `layer_oneshot` で重ねるレイヤーの中の、上のいずれか

layer_hold と layer_oneshot でしか入らないレイヤーは、離せば（次のキーで）戻るので調べない。
どこからも参照されないレイヤーと、2×2 より小さな月の表示（`widget: month`）は、警告だけを出す。

## 旧形式

トップレベルに `keys` と、`touch` の `cols`、`rows`、`cells` を書く形式も、そのまま読める。
読み込むときに、`name: base` のレイヤー 1 つに置き換える。

```yaml
keys:
  KEY_A: LCTRL+Z
touch:
  device: mxs-lradc-ts
  cols: 4
  rows: 3
  min_x: 226
  max_x: 3938
```
