# 設定ファイルの形式

`/etc/lefthand/config.yaml` の形式。YAML と JSON のどちらでも書ける。JSON は YAML の一部なので、同じファイル名のまま JSON を書いてもよい。
設定 GUI（WebSerial）も、この形式をそのまま読み書きする。

- **検証**：`lefthand -check config.yaml` で、デーモンを起動せずに検証できる。誤りはすべてまとめて表示する。
- **JSON への変換**：`lefthand -dump-json config.yaml` は、検証したうえで、旧形式を layers の形にそろえた JSON を出力する。割り当ては、すべてオブジェクトの形（`{"key": "B"}`）になる。
- **知らない項目**：書き間違いを見逃さないよう、知らない項目があると読み込みに失敗する。
- **設定 GUI で保存したとき**：デーモンが YAML で書き直す（`lefthand -check` を通る形）。割り当ては 1 行（`KEY_A: LCTRL+Z`、`"0,0": {key: B, label: ブラシ}`）で、項目は名前順になる。**手で書いたコメントは消える**。前の版は `config.yaml.prev` に残る。
- **設定 GUI で変えられない項目**：`hid_device`、`keyboard`、`touch.device`、`touch` の有無、`display`（`press_style` を除く）は、開いているデバイスにかかわるので、動作中のデーモンには反映できない。ファイルを直接編集し、サービスを再起動する。プロトコルは [protocol.md](protocol.md)。

## 全体

```yaml
hid_device: /dev/hidg0      # 送信先。省略可
keyboard: brain-kbd-i2c     # 本体キーボード。パスかデバイス名。省略可
touch: { ... }              # タッチパネルそのものの設定。省略するとタッチと画面を使わない
layers: [ ... ]             # レイヤー。最初のものが base
display: { ... }            # 画面表示。省略可
```

| 項目 | 型 | 内容 |
| --- | --- | --- |
| hid_device | 文字列 | 既定は `/dev/hidg0` |
| keyboard | 文字列 | 既定は `brain-kbd-i2c` |
| touch | オブジェクト | 下を参照 |
| layers | 配列 | 1 つ以上。下を参照 |
| display | オブジェクト | enabled（真偽）、device（既定 `/dev/fb0`）、vt（0 で自動）、rotate（0、90、180、270）、press_style（下を参照） |

## touch：タッチパネル

どのレイヤーでも共通の、ハードウェアの設定。格子の大きさとセルは、各レイヤーに書く。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| device | 文字列 | 既定は `mxs-lradc-ts` |
| swap_xy | 真偽 | パネルの X 軸が画面の縦方向のとき true |
| min_x、max_x、min_y、max_y | 整数 | 画面の端に当たる生の座標。`lefthand -calibrate` で測る。min > max なら軸を反転 |
| soft_areas | オブジェクト | ソフトキーの名前 → 範囲。範囲は `{ x: [a, b], y: [c, d] }` で、パネルの生の座標（swap_xy の影響を受けない）。a と b の順はどちらでもよい |

## layers：レイヤー

```yaml
layers:
  - name: base              # 必須。ほかのレイヤーから参照する名前
    label: "基本"           # 画面の隅に出す名前。省略すると name
    keys: { ... }           # 本体キーの割り当て
    touch:                  # タッチの格子
      cols: 4
      rows: 3
      cells: { ... }
    soft_keys: { ... }      # ソフトキーの割り当て
```

- **base**：最初のレイヤーが base になる。名前は何でもよいが、`base` を勧める。base はいつも一番下にあり、外れない。
- **重なり**：layer_hold などで入ったレイヤーは、base の上に、入った順に積まれる。いちばん上が「今のレイヤー」で、画面の右上に label を表示する。
- **透過**：割り当てを探すときは、いちばん上から順に見る。書いていないキー・セル・ソフトキーは、下のレイヤーの割り当てを使う。
- **none**：`none` と書くと、そこで探すのを止めて何もしない。下のレイヤーの割り当ても使わない。

### keys

左に Linux のキー名（`KEY_Q` など）、右に割り当てを書く。PW-SH2 のキー名は [keymap-pwsh2.md](keymap-pwsh2.md) を参照。

### touch

| 項目 | 型 | 内容 |
| --- | --- | --- |
| cols、rows | 整数 1〜16 | 格子の列数と行数。base 以外では、両方とも省略すると base と同じ大きさ |
| cells | オブジェクト | `"列,行"` → 割り当て。左上が `"0,0"` |
| background | 文字列 | 格子全体に敷く壁紙（背景画像の id）。下の「背景画像」 |

- **格子の大きさ**：上から見て、最初に touch を持つレイヤーの格子を使う。touch を書いていないレイヤーは、下のレイヤーの格子をそのまま使う。
- **セルの透過**：格子の大きさが下のレイヤーと同じあいだだけ、書いていないセルは下のレイヤーのものを使う。大きさが違えば、書いていないセルは空になる。
- **判定**：触れた瞬間に、今の格子で決まる。指を滑らせても、レイヤーが変わっても、離すまで変わらない。

### soft_keys

`touch.soft_areas` の名前 → 割り当て。割り当てがある区画だけが、格子のセルより優先される。
今の重なりで割り当てがない区画を押すと、格子のセルとして扱う。

## 割り当て

キー・セル・ソフトキーのどれにも、同じ形で書く。

| 書き方 | 意味 |
| --- | --- |
| `LCTRL+Z` | キーを送る。`+` でつなぐ。大文字小文字は区別しない |
| `none` | 何もしない（下のレイヤーも使わない） |
| `{ key: LCTRL+Z, label: "取り消し" }` | キーを送る。label は画面のセルに大きく出す。`\n` で改行 |
| `{ layer_hold: edit }` | 押しているあいだ、edit を重ねる |
| `{ layer_toggle: edit }` | 押すたびに、edit を重ねる・外す |
| `{ layer_oneshot: edit }` | 次に押した 1 キーだけ、edit を重ねる。もう一度押すと取り消す |
| `{ layer_to: edit }` | base と edit だけにする（ほかの重なりは外す）。`layer_to: base` で base だけに戻る |
| `{ mouse: left }` | マウスの操作。下の「マウスの操作」 |
| `{ usb_mode: toggle }` | USB の形の切り替え（マウスのオンとオフ）。下の「USB の形の切り替え」 |

- **オブジェクトの形**：`key`、`layer_hold`、`layer_toggle`、`layer_oneshot`、`layer_to`、`mouse`、`usb_mode` のうち、ちょうど 1 つを書く。`label` はどれにも付けられる。ウィジェットのセル（下の「ウィジェット」）では、どれも書かなくてよい。
- **セルの大きさ**：タッチのセルには `span: [列数, 行数]` を書ける（下の「セルの大きさ」）。
- **送れるキーの名前**：修飾キー（LCTRL、LSHIFT、LALT、LGUI、RCTRL、RSHIFT、RALT、RGUI）、A〜Z、0〜9、F1〜F12、ENTER、ESC、BACKSPACE、TAB、SPACE、INSERT、DELETE、HOME、END、PAGEUP、PAGEDOWN、UP、DOWN、LEFT、RIGHT、テンキー（KP0〜KP9、KPPLUS、KPMINUS、KPASTERISK、KPSLASH、KPDOT、KPENTER）、MINUS、EQUAL、LEFTBRACE、RIGHTBRACE、BACKSLASH、SEMICOLON、APOSTROPHE、GRAVE、COMMA、DOT、SLASH。
- **配列によらない記号**：記号は US 配列での位置を送るので、PC が日本語配列だと別の文字になることがある。`+` などはテンキーの名前で送ると配列によらない。例：Ctrl++ は `LCTRL+KPPLUS`。
- **レイヤーのセルの表示**：layer_* のセルは紫で描く。label を省略すると、行き先のレイヤーの label を大きく、切り替えの種類（押す間、切替、1回、移動）を下に小さく出す。

### マウスの操作（mouse）

```yaml
KEY_A: { mouse: left }                       # 押しているあいだ左ボタンを押す（ドラッグにも使える）
"3,1": { mouse: right, label: 右 }           # セル
"3,2": { mouse: scroll_down }                # 1 段送り、押し続けると繰り返す
```

| 値 | 動き |
| --- | --- |
| `left`、`right`、`middle` | そのボタンを、押しているあいだ押したままにする |
| `scroll_up`、`scroll_down` | 縦のホイールを 1 段回す。押し続けると、0.35 秒後から 0.07 秒ごとに繰り返す |
| `scroll_left`、`scroll_right` | 横のホイール（AC Pan）を同じように回す |

- **使える場所**：キー、タッチのセル、ソフトキー。ウィジェットのセルのタップにも書ける（`todo`、`calendar`、`trackpad` を除く）。
- **セルの表示**：label を省略すると「左クリック」「スクロール↓」などを大きく出す。label を書けば、それを大きく、操作の名前を下に小さく出す。
- **離すとき**：キーと同じく、押したときの割り当てで離す。そのうえで、**レイヤーが変わったときは、押しているマウスのボタンをすべて離す**（切り替えを起こした入力そのもののボタンは残す。layer_oneshot のレイヤーで押したボタンを、押したまま使えるようにするため）。設定の再読み込みと、デーモンの終了でも離す。
- **ボタンの重なり**：複数の入力で同じボタンを押しているときは、すべて離すまで押したまま。
- **USB**：USB がキーボードだけの形（起動したときの形）のあいだは、何も送らない。下の `usb_mode` でマウスをオンにする。

### USB の形の切り替え（usb_mode）

```yaml
"3,3": { usb_mode: toggle }                  # 押すたびに、マウスのオンとオフを切り替える
KEY_F1: { usb_mode: mouse, label: マウス }    # マウスをオンにする
```

| 値 | 動き |
| --- | --- |
| `toggle` | キーボードだけ ⇔ キーボードとマウス |
| `mouse` | キーボードとマウスの形にする（すでにそうなら何もしない） |
| `keyboard` | キーボードだけ（ブートキーボード）の形にする |

- **起動したとき**：キーボードだけ（ブートキーボード。BIOS や UEFI の画面でも使える）。
- **USB を付け直す**：2〜3 秒、キー入力、SSH、シリアル（設定 GUI）が切れる。押しているキーとマウスのボタンは、先にすべて離す。
- **セルの表示**：label を省略すると「マウス切替」「マウスオン」「マウスオフ」を出す。
- **使える場所**：キー、タッチのセル、ソフトキー、ウィジェットのタップ。

### セルの大きさ（span）

```yaml
"0,2": { key: ENTER, span: [3, 1], label: "決定" }   # 0,2 から右へ 3 列ぶん
"0,0": { widget: clock, span: [2, 2] }               # 2 列 × 2 行
```

- **書き方**：`[列数, 行数]`。それぞれ 1〜16。書かなければ `[1, 1]`。セルの番号は左上のセルで書き、右と下に広がる。
- **使える場所**：タッチのセルだけ。本体キーとソフトキーには書けない。
- **押したとき**：覆う範囲のどこを押しても、そのセルを押したことになる。押したときの枠も、範囲全体に描く。
- **格子からはみ出す、重なる**：誤りになる。同じレイヤーの中で、span の範囲に別のセルを書いたときも誤り（両方のセルに誤りを出す）。
- **レイヤーの透過**：span のセルは、覆う範囲がすべて上のレイヤーで空いているときだけ出る。一部でも上のレイヤーのセル（`none` を含む）に隠れると、そのセルは出ず、隠れていない範囲は空になる。
- **格子の大きさが違うレイヤー**：今までどおり透過しない。

### ウィジェット

タッチのセルに、キーの代わりに情報を出す。今あるのは時計（`clock`）、テキスト（`text`）、Todo（`todo`）、カレンダー（`calendar`）、トラックパッド（`trackpad`）。

```yaml
"0,0": { widget: clock }                                       # 時刻と日付。既定の書式
"2,0": { widget: clock, format: "15:04:05", date_format: none } # 秒まで出す。日付は出さない
"3,0": { widget: clock, tz: America/Los_Angeles, label: LA, key: F5 }  # 見出しを付け、タップで F5 を送る
"2,1": { widget: text, id: build, label: ビルド }                # テキスト。中身は PC の brain-deck で書き換える
"0,0": { widget: todo, span: [2, 3], label: Todo }              # Todo の一覧。長押しで完了を切り替える
"0,0": { widget: calendar, span: [2, 3], label: 予定 }          # 今日の予定と次の予定
```

| 項目 | 内容 |
| --- | --- |
| `widget` | ウィジェットの種類。`clock`、`text`、`todo`、`calendar`、`trackpad` |
| `label` | セルの上に小さく出す見出し（省略可） |
| `key`、`layer_*`、`mouse` | タップしたときの動き（省略可）。書けば、ふつうのセルと同じく働き、押したときに枠が光る。書かなければ、タップしても何もせず、枠も光らない。`todo`、`calendar`、`trackpad` には書けない（押した位置で働くため） |
| `span` | セルの大きさ。上を参照 |

- **使える場所**：タッチのセルだけ。本体キーとソフトキーには書けない。
- **`key: none` は書けない**：ウィジェットを出すだけなら、key を省略する。
- **描き直し**：ウィジェットごとに、中身が次に変わる時刻まで待って、変わったセルだけを描き直す。描画は今までどおり別のスレッドで行い、入力の処理を待たせない。壁時計が NTP などで飛んでも、1 分以内には表示が追いつく。
- **データ**：テキスト、Todo、カレンダーの中身は、設定ファイルではなく `/var/lib/lefthand/` に置く。設定 GUI で設定を保存しても消えない。
- **ほかの種類の項目**：`format` などの時計の項目をテキストに、`id` を時計に、`rows` と `page_reset` を Todo とカレンダー以外に、`stale` と `calendars` をカレンダー以外に、トラックパッドの項目をトラックパッド以外に書くと誤り。

#### 時計（clock）

| 項目 | 既定 | 内容 |
| --- | --- | --- |
| `format` | `15:04` | 時刻の行の書式 |
| `date_format` | `1月2日({wday})` | 日付の行の書式。`none` で出さない |
| `tz` | Brain のタイムゾーン | IANA の名前（`Asia/Tokyo`、`America/Los_Angeles`、`UTC` など）。知らない名前は誤り |

- **書式**：Go の `time.Format` の書き方。基準の日時「2006 年 1 月 2 日（月）15 時 04 分 05 秒」を、出したい形で書く。

  | 書き方 | 意味 | 例 |
  | --- | --- | --- |
  | `2006`、`06` | 年 | 2026、26 |
  | `01`、`1`、`Jan`、`January` | 月 | 10、10、Oct、October |
  | `02`、`2`、`_2` | 日 | 06、6、` 6` |
  | `15`、`03`、`3`、`PM` | 時 | 09、09、9、AM |
  | `04`、`4` | 分 | 05、5 |
  | `05`、`5`、`.000` | 秒、ミリ秒 | 07、7、.120 |
  | `Mon`、`Monday` | 曜日（英語） | Tue、Tuesday |
  | `{wday}` | 曜日（日本語 1 文字。lefthand の独自の書き方） | 火 |
  | `-07:00` | UTC からのずれ | +09:00 |

- **大きさ**：時刻の行は、セルに収まるいちばん大きな倍率（最大 10 倍）で描く。日付の行は最大 3 倍。
- **描き直しの間隔**：1 分に 1 回、分が変わった直後に描き直す。書式に秒（`05`、`5`、`.000` など）があるときだけ、1 秒に 1 回。
- **時刻を合わせていないとき**：Brain を起動してから一度も時刻を合わせていない（設定 GUI がつないでいない、NTP で合っていない）あいだは、時刻を橙色で描き、日付の行の代わりに「時刻未設定」と出す。合わせ方は README の「時刻合わせ」。

#### テキスト（text）

```yaml
"2,1": { widget: text, id: build, label: ビルド }
"0,2": { widget: text, id: note, span: [3, 1] }     # 横長のタイル
```

| 項目 | 内容 |
| --- | --- |
| `id` | 必須。中身の名前。英数字と `_ . -` の 32 文字まで。同じ id のセルをいくつ置いてもよい（どれも同じ中身） |

- **中身**：設定には書かない。PC から `brain-deck text <id> "..."`（プロトコルの `set_text`）で書き換え、Brain の `/var/lib/lefthand/text.json` に残る。デーモンや Brain を再起動しても残る。一度も書いていない id は、灰色で「未設定」と出る。
- **色**：`normal`（白）、`ok`（緑）、`error`（赤）、`warn`（黄）。

  | 種類 | ふつう | 有効期限が切れたとき |
  | --- | --- | --- |
  | normal | #ffffff | #6a7480 |
  | ok | #50d880 | #2e5a44 |
  | error | #ff5858 | #6a343a |
  | warn | #ffc030 | #6a582c |

- **有効期限**：書くときに `--ttl` を付けると、その時刻を過ぎたら、消さずに薄い色で描く。描き直しは、期限の時刻に 1 回だけ。
- **大きさ**：セルに収まるいちばん大きな倍率（最大 6 倍）で描く。セルの幅で折り返す（空白があれば空白で、なければ文字の境目で）。改行（`\n`）も使える。等倍でも入りきらなければ、入るところまで描いて「…」で切る。
- **長さ**：200 文字、8 行まで。
- **描き直し**：中身が変わったとき（`set_text`）と、期限が切れたときだけ。

#### Todo（todo）

```yaml
"0,0": { widget: todo, span: [2, 3], label: Todo }   # 縦長の一覧。1 ページに入るだけ並べる
"2,1": { widget: todo, rows: 3, span: [2, 1] }       # 1 ページ 3 行
```

| 項目 | 内容 |
| --- | --- |
| `rows` | 1 ページに並べる項目の数（1〜20）。省略すると、セルの高さに入るだけ並べる（1 行 52 ドット） |
| `page_reset` | ページを送ってから、触らずにこの時間がたつと 1 ページ目に戻る（`30s`、`2m` など。5 秒〜24 時間。既定 `1m`）。`off` で戻らない |

- **中身**：設定には書かない。設定 GUI の「Todo」タブか、PC の `brain-deck todo add "..."`（プロトコルの `todo_add` など）で書き換え、Brain の `/var/lib/lefthand/todo.json` に残る。Todo のセルを複数置くと、どれも同じ一覧を出す（ページは別々）。
- **並び**：未完了の項目を並べた順に出し、その下に完了した項目を出す。完了した項目は消さずに、薄い色（#6a7480）、塗った箱、取り消し線で描く。完了をまとめて消すのは、GUI の「完了した項目を消す」か `brain-deck todo clear-done`。
- **1 行**：左にチェックの箱、右に項目の文。文は 1 行で、入りきらなければ「…」で切る。文字の大きさは行の高さで決める（最大 3 倍）。
- **見出し**：`label` のあとに、残り（未完了）の件数を出す（「Todo 残り 3」。すべて完了なら「Todo すべて完了」）。`label` がなくても件数を出す。項目がなければ `label` だけ。
- **ページ送り**：入りきらないときは、セルの下に帯を出す。左の ▲ で前のページ、右の ▼ で次のページ、中央にページ番号（`1/3`）。押した瞬間にページを変える。これ以上送れない向きの矢印は暗くする。画面右の帯の ▲▼ は、本番の設定でレイヤーの切り替えに使っているので、Todo の帯は別に設けた。
- **完了の切り替え**：項目を **0.5 秒押し続ける**と、完了と未完了を切り替える（誤って触れても変わらない）。押しているあいだ、その行を黄色で塗る。0.5 秒より前に離すと、何もしない。切り替えると、項目は完了の側（下）か未完了の側へ移る。
- **押したときの見た目**：Todo のセルは押した位置で働くので、セル全体の枠は光らせず、押した行や矢印だけを黄色にする（`press_style` によらない）。
- **数**：上限はない。1 項目は 200 文字まで、改行は空白になる。
- **描き直し**：一覧が変わったとき、ページを送ったとき、押したとき・離したとき、`page_reset` で 1 ページ目に戻ったときだけ、そのセルを描き直す。実機で、2×3 のセル 1 つの描き直しは 10〜30 ms。

#### カレンダー（calendar）

```yaml
"0,0": { widget: calendar, span: [2, 3], label: 予定 }            # 縦長。今日の予定と次の予定
"2,1": { widget: calendar, span: [2, 1], calendars: [家], label: 家 } # 「家」のカレンダーだけ
"3,2": { widget: calendar, rows: 3, stale: 1h }                   # 1 ページ 3 行。1 時間で古いと出す
```

| 項目 | 内容 |
| --- | --- |
| `rows` | 1 ページに並べる行の数（1〜20）。省略すると、セルの高さに入るだけ並べる（1 行 52 ドット） |
| `page_reset` | ページを送ってから、触らずにこの時間がたつと、触っていないときのページに戻る（既定 `1m`、`off` で戻らない） |
| `stale` | 最終更新がこれより古ければ、最終更新の行を橙色にして「古い」と出す（`1m`〜`720h`。既定 `3h`） |
| `calendars` | 出すカレンダーの名前（brain-deck の calendars.yaml の `name`）。省略するとすべて |

- **中身**：設定には書かない。PC の `brain-deck calendar sync`（プロトコルの `set_calendar`）が ICS の URL から取ってきて送り、Brain の `/var/lib/lefthand/calendar.json` に残る。繰り返しの予定とタイムゾーンは PC で解き、Brain には時刻の決まった予定と、日付だけの終日の予定が届く。
- **並び**：今日の予定を、終日の予定（今日をすべて含む予定も）、始まりの時刻の順に並べ、そのあとに、今日より先のいちばん早い予定を 1 つ（「次の予定」）並べる。今日の予定がなければ「今日の予定はありません」と出す。

  | 行 | 時刻の欄 | 見た目 |
  | --- | --- | --- |
  | 終日 | `終日` | ふつう |
  | 今の予定 | 終わりの時刻（`〜10:30`）。今日のうちに終わらなければ `今` | 行を青（#1e4a7c）で塗る |
  | これからの予定 | 始まりの時刻（`13:00`） | ふつう |
  | 終わった予定 | 始まりの時刻（前の日から続いた予定は `〜06:00`） | 薄い色（#6a7480）。左の帯も薄く |
  | 次の予定 | `明日 10:00`、`10/9(金) 10:00`、終日なら `明日`、`10/9(金)` | ふつう |

- **1 行**：左にカレンダーの色の帯、時刻の欄、予定の名前。名前は 1 行で、入りきらなければ「…」で切る。文字の大きさは行の高さとセルの幅で決める（最大 3 倍）。
- **最終更新**：いちばん下に「更新 10:35」（今日でなければ「更新 10/6 10:35」）を小さく出す。カレンダーが複数あれば、いちばん古いもの。次のときは橙色にする：`stale` より古い（「古い」を足す）、取得に失敗したカレンダーがある（「失敗 1」を足す。前の予定は残っている）、Brain の時刻を合わせていない（「時刻未設定」）。予定を一度も受け取っていなければ、中央に「予定を受け取っていません」と出す。
- **ページ送り**：Todo と同じく、入りきらないときはセルの下の ▲▼ で送る。触っていないときは、今の予定か、これからの予定がある最初のページを出す（朝の予定が多くても、今の予定が見える）。予定の行を押しても何もしない。
- **時刻**：「今日」と時刻は Brain のタイムゾーンで決める。Brain の時刻が遅れていると、今の予定がずれるので、`brain-deck calendar sync` は予定を送る前に時刻を合わせる。
- **描き直し**：予定が始まる時刻と終わる時刻、日付が変わる時刻、最終更新が古くなる時刻、予定を受け取ったとき、ページを送ったときだけ、そのセルを描き直す。実機で、2×3 のセルの描き直しは 20〜40 ms、予定の始まりと終わりの時刻から描き終わるまで 30 ms ほど。

#### トラックパッド（trackpad）

```yaml
"0,0": { widget: trackpad, span: [3, 4], label: トラックパッド }                 # 値は既定値
"0,0": { widget: trackpad, span: [3, 3], speed: 1.5, accel: 0.5, scroll_width: 0 } # 速く、加速を弱く、帯なし
```

セルの中で指を動かすとカーソルが動く。短いタップで左クリック、タップしてすぐ触れて動かすとドラッグ、右端の帯をなぞると縦のスクロール。
操作の説明は README の「マウスとトラックパッド」。項目はどれも省略でき、省略すると既定値。

| 項目 | 範囲 | 既定 | 内容 |
| --- | --- | --- | --- |
| `speed` | 0.05〜20 | 1.0 | 感度。画面の 1 ドットの動きを、マウスの何カウントにするか（ゆっくり動かしたとき） |
| `accel` | 0〜10 | 1.0 | 加速。速さ v（ドット/秒）のとき speed × (1 + accel × min(v/1000, 3)) 倍。0 で加速しない |
| `scroll_width` | 0〜400 | 72 | 右端のスクロールの帯の幅（ドット）。セルの右端から数える。0 で帯なし |
| `scroll_direction` | `natural`、`traditional` | `natural` | natural は指を下へ動かすと中身が下へ動く（上へスクロール。スマホと同じ）。traditional はホイールと同じ（指を下へ＝下へスクロール） |
| `scroll_step` | 2〜400 | 24 | ホイール 1 段に当たる指の動き（ドット） |
| `settle_ms` | 0〜500 | 30 | 触れてから、この時間のサンプルを捨てる（触れた瞬間の跳ね） |
| `smooth` | 1〜10 | 3 | 最後のこの数のサンプルの平均を使う |
| `deadzone` | 0〜50 | 1.5 | 平均の位置が、この距離（ドット）より動かなければ無視する。止めているときの揺れと、動き始めの小さな動き |
| `min_pressure` | 0〜4095 | 0 | 押す強さ（ABS_PRESSURE）がこれより小さいサンプルを捨てる。0 で見ない |
| `tap_ms` | 30〜1000 | 180 | これより短く触れて離せばタップ |
| `tap_move` | 0〜200 | 12 | タップとみなす動きの上限（ドット。触れた位置からいちばん離れた距離） |
| `drag_ms` | 0〜1000 | 200 | タップのあと、左ボタンを押したまま次のタッチを待つ時間。そのあいだに触れて動かすとドラッグ、すぐ離すとダブルクリック。過ぎるとボタンを離す（クリック）。0 にすると、タップですぐクリックする |
| `long_press` | `none`、`right` | `none` | right なら、0.6 秒動かさずに押すと右クリック |

- **判定のしかた**：触れた位置がトラックパッドのセルなら、離すまでのサンプルをすべてトラックパッドで使う（指がセルの外に出ても動かし続ける）。触れた位置が帯なら、そのタッチはスクロールだけ（カーソルは動かさない）。
- **離す直前**：最後のサンプルは 1 つ遅らせて使い、離したときに捨てる（離す瞬間の跳ね）。
- **ほかのセルに触れたとき**：タップのあとの待ち（`drag_ms`）のあいだにほかのセルに触れたら、待たずにクリックを終える。
- **レイヤーの切り替え、設定の再読み込み**：ドラッグやタップの待ちをやめ、ボタンを離す。そのタッチは、指を離すまで何もしない。
- **描き直し**：見出しと帯は、レイヤーを描くときに描くだけ。触っているあいだは描き直さない。押したときの枠も出さない。
- **マウスがオフのとき**：USB がキーボードだけの形のあいだは、セルの中央に「マウスはオフ」と出し、触っても何もしない（`usb_mode` で切り替える）。
- **書けない項目**：`key`、`layer_*`、`mouse`（タップはクリックになるため）。`format` など、ほかのウィジェットの項目。

### 背景画像（background）

```yaml
layers:
  - name: base
    touch:
      cols: 4
      rows: 3
      background: 7f8f231d4a49bfee                                   # 壁紙
      cells:
        "0,0": { key: LGUI+S, label: 保存, background: b18c7e1fecc29a03 } # セルの背景
        "2,0": { widget: clock, span: [2, 1], background: c1ee527da7f58e93 }
```

| 書く場所 | 内容 |
| --- | --- |
| レイヤーの `touch.background` | 壁紙。画面全体（800×480）の画像。セルの隙間と、背景画像のないセルの中に見える |
| セルの `background` | セルの背景。セルの枠の内側（セルの範囲から 4 ドット内側。4×3 なら 192×152、span なら覆う範囲全体）の画像 |

- **値**：背景画像の id。画像ファイル（`/var/lib/lefthand/images/<id>.565`）の SHA-256 の先頭 16 文字（16 進の小文字）。ふつうは設定 GUI が書く。形が違えば誤り。
- **ファイルの形**：先頭 8 バイトが `LHI1`、幅、高さ（リトルエンディアンの uint16）。続けて左上から行の順に、1 画素 2 バイトの RGB565（リトルエンディアン）。1 枚 800×480 まで（各辺 800 まで、384,000 画素まで）。
- **使える場所**：タッチのセルだけ（キー、ウィジェット、span のどのセルでも）。本体キーとソフトキーには書けない（誤り）。割り当てのないセルには置けない（壁紙は見える）。
- **重ね方**：画面の黒 → 壁紙 → セルの塗り（壁紙があれば壁紙のまま）→ セルの背景画像。そのうえに枠とラベル。
- **縁取り**：壁紙かセルの画像があるセルでは、文字（ラベル、送信キー、ウィジェットの文字）に、文字の点を上下左右と斜めに 1 ドット広げた黒い縁取りを付ける。縁取りもセルの内側（textMargin）からはみ出さない。gui/src/preview.ts と同じ描き方。
- **押したとき**：`border` は画像の上に二重の枠を描き、離すと枠の帯だけを画像で描き直す。`fill` は黄色で塗りつぶす（そのあいだ画像と縁取りは出ない）。
- **壁紙の透過**：セルと同じ。上から見て、格子の大きさが同じあいだのレイヤーで、いちばん上にある `touch.background` を使う。cols と rows を省略した touch（`touch: { background: ... }`）は、base と同じ大きさの、セルのない格子になる。
- **ない画像、大きさの違う画像**：誤りにはしない（設定は使える）。ない画像は背景なしで描き、大きさが違う画像は中央に置いて、はみ出す分は切る。どちらも `lefthand -check`（`-data-dir` か `-render-images` の画像で調べる）、起動時、validate と set_config の warnings に出る。

### 動き方の細かい決まり

- **押したまま切り替えたとき**：キーは、押したときの割り当てで離す。たとえば edit で Ctrl+C を押したまま edit を抜けても、離したときに Ctrl+C を離す。
- **layer_hold**：押したキーを離すと、そのキーで重ねたレイヤーだけを外す。ほかの重なりはそのまま。
- **layer_toggle**：そのレイヤーが layer_toggle か layer_to で重なっていれば外し、なければ重ねる。上のレイヤーで同じキーを書かなければ、透過して base の layer_toggle が働くので、同じキーで戻れる。
- **layer_oneshot**：layer_* 以外の入力を押したとき（割り当てのないキーを含む）に、押したキーの割り当てを決めてから外れる。
- **layer_to**：重なりを全部外してから、行き先を重ねる。layer_hold で押しているキーを離しても、もう何も外れない。
- **オートリピート**：無視する。リピートは PC 側に任せる。

## 画面の表示

- **右上の札**：今のレイヤーの label を出す。色で入り方がわかる。
- **色**：base だけのときは青、layer_toggle か layer_to で入ったとき（離しても戻らない）は緑、layer_hold か layer_oneshot で入ったとき（一時的）は橙。セルの枠も同じ色になる。
- **描き直し**：レイヤーが変わると、画面全体を描き直す。描画は別のスレッドで行い、キー入力の処理を待たせない。

### 押しているセルの見せ方（display.press_style）

```yaml
display:
  press_style: border   # border（既定）か fill
```

| 値 | 押しているあいだの見た目 | 描き直す範囲 |
| --- | --- | --- |
| `border` | セルの内側に二重の枠を描く。外側 2 ドットが黒、内側 5 ドットが黄色（#ffd040）。セルの中身とラベルはそのまま | 枠の帯だけ |
| `fill` | セル全体を黄色で塗りつぶし、ラベルを黒で描く（以前の見せ方） | セル全体 |

- **既定**：書かないと `border`。それ以外の値は誤り。
- **二重の枠の理由**：外側の暗い線があるので、明るい色や画像の背景の上でも枠の縁が分かる。枠はラベルの余白（8 ドット）より細いので、ラベルには重ならない。
- **離したとき**：ふだんの枠（2 ドット、レイヤーの入り方の色）に戻す。
- **割り当てのないセル**：押しても見た目は変わらない。
- **反映**：`display` のほかの項目と違い、設定 GUI から保存すれば、デーモンを再起動せずにすぐ反映する。
- **確かめ方**：`lefthand -render-png out.png -render-pressed "0,0" config.yaml` で押した画面を書き出せる。`-render-press-style fill` で、設定と違う見せ方も試せる。

## 読み込み時の検証

次のものは誤りとして、デーモンを起動しない。

| 誤り | 例 |
| --- | --- |
| 存在しないレイヤーの参照 | `layer_hold: nope` |
| base に戻れないレイヤー | layer_toggle か layer_to で入るのに、戻る手段がない。layer_to どうしで行き来するだけで base に戻れない輪も含む |
| base への layer_toggle | base は外せないので、layer_to を使う |
| レイヤー名の重複・名前なし | |
| 割り当ての書き方 | key と layer_* を両方書いた、どれも書いていない、知らない項目 |
| 知らないキー名 | `KEY_NOPE`、`LCTRL+NOPE` |
| 格子の外のセル、同じセルの重複 | 4x3 の格子に `"4,0"` |
| span がはみ出す、重なる | 4x3 の格子の `"3,0"` に `span: [2, 1]` |
| 背景画像の書き方 | id が 16 文字の 16 進でない、本体キーやソフトキーの `background` |
| ウィジェットの書き方 | 知らない `widget`、知らない `tz`、widget なしの `format`、本体キーやソフトキーの `widget`・`span`、ウィジェットに `key: none`、`todo`、`calendar`、`trackpad` に `key` や `layer_*` や `mouse`、`rows` が 1〜20 の外、`page_reset` や `stale` の時間の誤り、トラックパッドの項目の範囲の外、トラックパッド以外のトラックパッドの項目 |
| マウスの操作 | 知らない `mouse` の値、知らない `usb_mode` の値 |
| 定義していないソフトキー | soft_areas にない名前を soft_keys に書いた |
| base の格子がない | touch があるのに、base に cols/rows がない |
| 旧形式との混在 | layers と、トップレベルの keys（または touch.cells）を両方書いた |

**base に戻る手段**とみなすのは、そのレイヤーを base の上に重ねたときに押せる（透過も含む）、次のいずれか。

- `layer_to: base`
- そのレイヤー自身の `layer_toggle`
- base に戻れるレイヤーへの `layer_to`
- `layer_hold` か `layer_oneshot` で重ねるレイヤーの中の、上のいずれか

layer_hold と layer_oneshot でしか入らないレイヤーは、離せば（次のキーで）戻るので調べない。
どこからも参照されないレイヤーは、警告だけを出す。

## 旧形式

トップレベルに `keys` と、`touch` の `cols`、`rows`、`cells` を書く形式も、そのまま読める。

```yaml
  max_y: 384

    "0,0": { key: B, label: "ブラシ" }
```
