# 16. 分かっている制約と、保留にしていること

[目次に戻る](../architecture.md)

2026-10-12 の時点。新しく分かったら、ここと README の該当する節を直す。

## ハードウェアと OS の制約（直せない、直していない）

| 制約 | 中身 | どう扱っているか | 出どころ |
| --- | --- | --- | --- |
| **充電されない** | Brainux のカーネルには i.MX28 の電源と充電のドライバがなく、内蔵の充電器は止まったまま。USB につないでも電池は減る | 充電は純正のファームウェアで行う。電圧で守る（3.5 V で知らせ、3.4 V で保存して電源を切る）。充電器を動かす案は**保留**（作るならカーネルのドライバとして、Brain Hackers のコミュニティで見てもらう） | README の「充電」、PROGRESS.md |
| **USB をつなぐと電源が入る** | 電源を切ったあとでも、USB の 5V を差し込むと起動する（i.MX28 の働きと考えられる。AUTO_RESTART は 0） | 止める方法は見つけていない。「5V だけで起動したら、キーを押さなければ電源を切る」案は提案だけ | README の「電源の動き」 |
| **`\|` が本体キーで打てない** | 記号 + シフト + G は、キーボードのコントローラが G を知らせない（シフトだけが届く） | 端末モードのタッチのキーの 1 ページ目の `\|` を使う。ソフトでは直せない | README の「端末モード」、docs/keymap-pwsh2.md |
| **同時押しの制約** | ドライバは 1 回に最大 3 キーを読む。文字切り替え + Q を押したまま W は届かない。マトリクスにも同時押しできない組み合わせがある | 割り当てで避ける | docs/keymap-pwsh2.md の「同時押し」 |
| **区別できない・届かないキー** | 「調べる」と「戻る」はどちらも KEY_ESC。電源、ツール、ホーム、記号のキーはイベントが出ない（カーネルが処理する） | 割り当てられない | docs/keymap-pwsh2.md |
| **音が出ない** | ブザーは、デバイスツリーにピンの定義はあるが PWM のピンの設定に入っておらず、使えるデバイスになっていない。スピーカーで音を出せるか（ALSA など）は**調べた記録がない（未確認）** | ポモドーロなどの知らせは画面だけ（点滅） | REPORT.md のフェーズ A、docs/config.md |
| **IN のエンドポイントが 7 本** | NCM、HID、ACM 2 つで使い切っている。マウスを別の HID にできない | 1 つの HID にレポート ID で入れ、起動したときはブートキーボード。マウス、メディアキー、ペンは切り替えたときだけ | [2. USB の構成](02-usb.md) |
| **抵抗膜のタッチパネル** | 1 点だけ（マルチタッチなし）、ペンを浮かせた位置（ホバー）を読めない、触れた直後と離す直前に座標が跳ねる、26 ms ごと | 触れた瞬間のセルで決める、トラックパッドとペンはブレ対策 | trackpad.go、stroke.go |
| **CPU が 1 つで遅い** | 起動に約 60 秒（lefthand の準備まで約 70 秒。サービスを止める前は 84 秒と 86 秒）。YAML の解析は PC の約 150 倍。大きな画像は Brain で開かない | 重い処理は PC。描画の優先度を下げる。起動を速くする段階 1〜3（contrib/boot）を本番に適用した（2026-10-12） | README の「Brain の起動を速くする」 |
| **cgroup が使えない** | コントローラーが有効でない | 自分で足すアプリは ulimit（仮想メモリ）で制限 | REPORT.md のフェーズ K5 |
| **uinput がない** | カーネルに uinput がなく、本物のキーやタッチを自動で作れない。`/dev/input/event1` に書く試験は止められた | 実機のキーやふたの試験はユーザーが行う。タッチは記録と再生（`-record-touch`、`-replay-touch`） | record.go、PROGRESS.md |
| **RTC はドライバなしで読む** | `/dev/mem` から直接読む（カーネルの設定が変わると読めなくなるかもしれない） | 読めなければ使わない | rtc.go |

## 保留にしていること、決めてほしいこと

| 項目 | 状態 | 出どころ |
| --- | --- | --- |
| 内蔵の充電器を動かす | 保留（別の仕事。カーネルのドライバとして） | PROGRESS.md |
| 起動を速くするサービスの停止 | 決めて適用した（2026-10-12）：段階 1〜3（ly も止めた）。残る遅れは lefthand の起動中の約 12 秒（原因は確かめていない） | README の「Brain の起動を速くする」 |
| 自分で足すアプリの上限の既定 | 決めた（2026-10-12）：時間 10 秒、メモリ 32 MB、同時に 3 つ、出力 32 KiB。app.yaml で変えられ、設定の apps の上限（64 MB、60 秒、256 KiB）を超える値は断る | docs/apps.md、docs/config.md |
| 例のアプリを本番の設定に入れるか | 入れない（決めた） | REPORT.md |
| 「充電だけ」の動き（5V で起動したら電源を切る） | 提案だけ | README の「電源の動き」 |
| Brain が直接インターネットから予定を取る | 提案だけ（今は PC が取って送る） | REPORT.md のカレンダー |
| PC を NTP サーバーにする | 提案だけ（PC 側の設定はユーザーが行う） | README の「時刻合わせ」 |

## 作りの上で気をつけること

- **エンジンのロック**：`Engine.mu` を持ったまま、ウィジェットのタップの処理、通知（`onView`、`onStatus`、`onRotate`、`notify`）を呼ぶ。そこからエンジン（`Engine.Status`、`View` など）や設定の置き場所（`configStore`）のロックを取ると止まる。K1（設定の反映のとき）と K5（アプリのタップで、設定のアプリの写しを作ったとき。コミット d18b7d3）で実機で起きた。描画の goroutine も画面のロックを持ったままエンジンを読むので、同じ形に気をつける。
- **Go と TypeScript の描き方は 2 つある**：display.go などと gui/src/preview.ts など。fixture を使った画素単位の比べで合わせている。片方だけ変えるとテストが落ちる。
- **HID のディスクリプタは 2 か所にある**：hid.go と gadget-setup.sh。テストと `-check-gadget` で合わせている。
- **設定の項目を足したら反映も足す**：main.go の `cstore` の `apply`（と、上書きで変わるものは `light`）。足し忘れると、保存しても再起動するまで効かない。
- **データの書き込みは待たせない**：返事や入力の処理で SD カードを待たない形（保存の goroutine）にそろえる。
